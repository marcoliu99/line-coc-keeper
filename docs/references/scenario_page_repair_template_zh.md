# `repair_` 上傳的頁面修復範本

[English](scenario_page_repair_template.md)

用這個檔案修正對話中已載入的 PDF 劇本的部分實體頁。對照原始 PDF 填寫（可請 ChatGPT 或其他審稿者協助），存成 `repair_<名稱>.md` 後上傳。Bot 只會替換列出的頁面，發布新版本，原版不會被修改；任何一項檢查失敗就整份不套用。設計：`specs/feature/discord_page_level_scenario_repair_design_spec_zh.md`。

> 狀態：上傳功能正分階段交付，目前尚未啟用；範本與解析器已先上線，格式因此固定。

## 要從 Bot 抄什麼

不用計算，也不用複製雜湊。只要從 Bot 載入劇本的訊息（`已載入劇本《…》`、`共 N 頁（實體頁數）`）取兩個值：劇本標題與實體頁數。

## 規則

- 只能有**一個** `json` 區塊，區塊以外的內容會被忽略；任何地方出現未知的鍵都會被拒絕。
- `repair_version` 是 `1`。
- `target.title` 是載入訊息顯示的劇本標題，`target.page_count` 是 PDF 的實體頁數。為其他劇本、或頁數不同的 PDF 準備的檔案會被拒絕。
- `page` 是 **PDF 實體頁碼**（1 是 PDF 第一頁），不是書上印的頁碼。每頁一個物件，共 1 到 100 個，順序不拘。
- `text` 是該頁**完整**的修正後文字，會取代整頁；不支援局部修改。不要寫 `--- 第 N 頁 ---`：頁面標記由系統擁有。
- `page_kind`：`text`（一般頁面）、`map`（平面圖或示意圖：轉錄可讀的標籤，不要捏造房間描述，文字少是正常的）或 `image`（只在該頁真的沒有可讀文字、且有儲存的頁面圖片時使用，此時 `text` 必須是空的）。
- `review_note` 寫你對照 PDF 頁面檢查了什麼、修正了什麼，不能是空的。
- 你改動的每個數字都會私訊給 KP（`HP 10` → `HP 40`、`1D40` → `1D4`、`+10%` → `-10%`）。修正本來就可以改數字，回報是讓 Keeper 看得見改了什麼。

## 範本

```json
{
  "repair_version": 1,
  "target": {
    "title": "<載入訊息顯示的劇本標題>",
    "page_count": "<載入訊息顯示的實體頁數，填數字>"
  },
  "patches": [
    {
      "page": "<實體頁碼，填數字>",
      "text": "<該頁完整的修正後文字>",
      "page_kind": "text",
      "review_note": "<你對照 PDF 頁面檢查了什麼、修正了什麼>"
    }
  ]
}
```

每替換一頁就在 `patches` 加一個物件。
