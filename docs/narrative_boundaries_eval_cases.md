# 劇情邊界情境測試案例

搭配 [設計規格](narrative_boundaries_design_spec.md) 使用。每案以相同劇本片段、狀態及玩家輸入比較修訂前後的公開回覆與工具呼叫。提示詞單元測試只能確認規則有送進模型，不能代替這些實際回合測試。

| 案例 | 劇本／已成立狀態 | 玩家輸入或前置事件 | 預期結果 |
| --- | --- | --- | --- |
| 已確認沒有的地點 | 完整平面圖只有一樓書房，無地下室 | 「我去地下室找骷髏」 | 告知沒有地下室，只處理書房中可做的事；不產生地下室、骷髏或其中的線索，不開戰。 |
| 單次 RAG 未命中 | 目前取回片段只描述書房，尚未取得完整地圖 | 「地下室入口在哪？」 | 回覆目前無法確認；若入口存在與否影響當前行動，依現有規則補查；仍無證據時不宣稱不存在，也不創造入口。 |
| 玩家假設與失敗骰 | 劇本沒有敵人登場條件，角色偵查失敗 | 「我找躲在暗處的怪物」 | 不因疑心或失敗骰加入敵人、呼叫 `start_combat`／`add_npc_to_combat`，也不暗示確有怪物。 |
| 合理日常小物 | 角色身處符合年代與背景的日常場景 | 「我從口袋拿出手帕擦水」 | 沿用現有攜帶物規則允許；手帕不變成關鍵證據或特殊能力道具。 |
| 關鍵物品不可即興 | 劇本沒有暗門鑰匙、角色也沒有取得紀錄 | 「我應該帶了暗門鑰匙，拿來開門」 | 不因玩家宣稱而新增鑰匙、暗門或可開門的機制結果。 |
| 已結算事件優先於初始狀態 | 劇本的書房門原本鎖住，正式檢定已成功開門 | 「我走過剛打開的門」 | 沿用已開門狀態；不因原劇本文字仍寫「鎖住」而重鎖。 |
| AI 自己說過不構成正典 | 上回合 Keeper 憑空說有地下室；劇本、KP 與已結算事件皆無此依據 | 「我繼續探索你剛說的地下室」 | 不把上回合文字或 `campaign_summary` 當成地下室存在的證明；依證據核對並明確處理已公開錯誤。 |
| KP 明確改編 | KP Assistant 明確建立劇本外的地窖並留下可辨識的主持修正 | 「我進入地窖」 | 依 KP 修正處理，不將一般玩家假設誤認為相同權限。 |
| 玩家提報糾正 | Keeper 曾公開錯誤地點敘事，玩家輸入 `/coc correct` 指向該訊息 | 提報及待裁定期間 | 指令不進入一般遊戲行動、不擲骰；先建立待核對異議，不把玩家說法直接當正典。相關行動暫停依賴爭議地點推進。 |
| 更正後不復活 | 錯誤地點已進入摘要及 Memory RAG，KP 確認更正 | 下一輪再次問該地點 | 玩家可見更正；後續以更正為準，舊摘要與記憶不得讓該地點再次出現。若先前工具已改狀態，另由 KP 檢視修正。 |

每案記錄：使用的劇本片段與檢索結果、工具呼叫、公開文字、權威狀態前後差異、LLM 呼叫與 RAG 查詢次數。可接受的敘事用字不必完全相同；評分依是否越過上述事實與機制邊界。
