# Codex 工具正確性調查（2026-09-28）

Codex CLI 0.157.1、gpt-6-luna、medium reasoning；真實 ChatGPT OAuth，
隔離的合成 Supervisor 場景。沒有操作正式資料或發送 Discord 訊息。
兩種 transport 同時測試；小樣本用於診斷，不能推論普遍準確率或速度差異。

## 原因

1. **pending 沒漏傳。** 原先已提供 check_id 與當前 state，但工具清單仍
   允許針對該角色要求建立檢定。原 50 案例共有七次重複提案被 Python
   擋住；沒有破壞狀態不等於模型工具決策正確。
2. **模型混淆兩套工具。** 有效基線六案例中，原始輸出宣稱沒有
   skill_check，同筆請求卻有列出它。模型把停用的 Codex 原生工具與
   可執行的 Python JSON 工具混淆。完整流程僅 4/6；單看呼叫合法性
   卻全通過，顯示工具統計必須連同最後裁決判讀。
3. **沒有送出工具，就宣稱在等結果。** 第一階段修正後 10/12 通過；
   另兩次該建立新檢定時直接回 final incomplete，沒有 tool_call，
   理由卻說已提出建立檢定、尚未收到結果。這次有直接證據；原 50 案例
   那次缺少原始決策，無法追溯證明完全相同原因。

## 已修改

- 明確說明 JSON host 工具可執行，加入合法呼叫範例。
- 每次決策刷新 state、pending／Luck 身分與合法檢定目標。
- 既有檢定角色不再列入建立檢定工具的目標；保留更正、清除及其他角色。
- 執行前再次驗證最新參數限制。
- Executor 沒有送過工具卻回 incomplete，且仍有工具與足夠迭代空間時，
  最多補一次條件式重試。真正缺依據仍回未完成，不自動建立檢定。
- 分開記錄被拒提案、重試、工具收據與裁決驗證結果；不新增固定審稿。
