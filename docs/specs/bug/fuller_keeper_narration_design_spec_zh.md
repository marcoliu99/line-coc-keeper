# 守密人要把地點完整描述出來，而不是只寫一兩句

[English](fuller_keeper_narration_design_spec.md) | [文件索引](../../README.md)

類別：`bug`。狀態：**已實作**。基準：`main_v2` 的 `87413ae`。

## 問題

在一次《The Haunting》實跑中，守密人的一般回覆只有 60–180 字，而且很多以「尚未判定」「尚未辨清」「眼下還沒有確切線索」收尾（例如「你站在入口內……尚未辨清屋內各處的設施；要看清楚周遭，你得再往裡查看」）。玩家始終不知道那個地方有什麼，沒有東西可以接著調查，遊戲因此停滯。

原因出在提示。節奏規則寫「給出一個具體的反應點就停下來」，還說寫到第三段就代表該收了；再加上「不可發明劇本沒寫的內容」「不可提早透露劇本」，模型就把「什麼都不發明的最短回覆」當成最安全的寫法。

## 修改

只改 `app/prompt_builder.py` 的一條提示規則（Executor 與 Narrator 共用的節奏段落）：

- 一次回覆仍然只推進一個場景片段，但要寫完整：通常兩到四段、約 150–300 字。
- 調查員進入或查看一個地點時，把劇本寫在那裡的東西描述出來（陳設、物件、出入口、聲音、氣味、在場的人），讓玩家有東西可以調查。
- 劇本有寫的就直接描述，不能用「尚未判定」當整則回覆的主體；劇本沒寫的細節，用不新增關鍵線索的氛圍帶過，並點出玩家接下來可以做什麼。
- 進入新地點時可以寫得更長。

防雷、保密、「不可發明」的規則都不變。

## 不做

不在程式裡強制字數，不改降級訊息，不改地點索引或檢索。如果改完回覆還是太薄，下一個要查的是檢索（沒有地點索引的劇本，守密人可描述的內容較少），不是提示。

## 測試

沒有：這是提示用字。驗證方式是實跑，進入房間時的回覆應該把房間描述出來。
