# 劇本事件在同一回合的機械義務

[English](event_obligations_design_spec.md) | [文件索引](../../README_zh.md)

## 狀態與目標

分類：`bug`。狀態：**已實作**。來源：Camp Sunny 五人 500 回合驗證的 CS-007（Workstream C）。基於 `main_v2` 的 `aa79f22`。

斷手被揭露了。檢索到的劇本依據寫有看見它的 SAN 規則，敘事也展示了那隻手，但直到玩家之後說自己很害怕，才有 SAN 檢定：正典事件在故事裡發生了，在機制裡卻沒有。Narrator 拿到和 Executor 相同的劇本依據，不論 Executor 有沒有呼叫規則要求的工具，它都能敘述依據裡描寫的內容。

## 契約

1. **只讀劇本寫的內容**（`app/services/event_obligations.py`）。從該回合拿到的依據（主動檢索、那一次復原搜尋、Executor 自己的 `search_scenario` 結果）抽出三種明確規則：SAN 損失（`SAN 1/1D4`、`理智檢定 0/1d6`、`Sanity 0/1D3`）、帶觸發條件的傷害骰（`若有人觸碰祭壇…受到 1D6 點傷害`）、帶觸發條件的必要技能檢定（`走進地下室的人須通過困難聆聽檢定`）。沒有這類規則的氣氛式恐怖不產生任何東西；戰鬥攻擊排除在外；傷害與強制檢定必須有觸發詞。
2. **判斷事件已被呈現。** 每條規則帶有 *錨點*：規則之前那句話的關鍵詞（`斷手`、`水桶`），不含通用字詞。敘事包含全部錨點（超過兩個時為三分之二）才算觸發，所以只提到水桶、沒提到裡面的東西，不會產生義務。
3. **在敘事提交之前套用**（`app/agents/obligation_gate.py`，由 supervisor 在 Narrator 之後、一致性檢查／Guard／投遞之前呼叫；適用玩家行動與檢定結算後的接續）。對每條已觸發、且尚未套用到這位調查員的規則，依序且每回合最多四條：`sanity_check`、由 Python 擲傷害後呼叫 `adjust_character`、或 `skill_check`，都走一般工具路徑，所以 autoroll、待處理檢定、Luck、重傷與戰鬥的行為和其他呼叫一致。回覆每條義務會多一行固定文字，並重新整理交接，讓待處理檢定的指示被附上。
4. **冪等。** 工具執行之前先保留一筆帳本紀錄（`check_consequence_receipts`；識別為時間線＋角色＋規則，規則寫「每次」時再加上回合）。重播、重試或之後再次提到同一事件都會找到它而不做任何事；套用失敗或被擋下時會釋放保留，之後的回合可以再試。另一位看見同一事件的調查員各自承擔自己的義務。

## 保持不變的契約

狀態變更仍由確定性的工具負責；gate 只判斷有一件事該做，以及參數是什麼，參數取自劇本自己的句子。損失多少不由 LLM 決定。執行期沒有任何特定劇本的規則文字或觸發物。

## 執行方式

`tests/test_event_obligations.py`：兩種語言與骰式格式的規則讀取；氣氛式恐怖、戰鬥、沒有觸發詞的傷害都不產生義務；錨點判斷；同一則回覆同時帶有揭露與待處理 SAN 檢定；autoroll 結算；重播或之後再次提到不重複；第二位調查員；被擋下的套用會釋放並可重試；傷害走同一機制；強制技能檢定；以及只有 gate 會套用義務。拿掉帳本會讓重播與傷害測試失敗。

## 未涵蓋

規格偏好的順序（先導出義務、再敘事）沒有照字面做：事件是否發生只能從 Narrator 呈現的內容得知，所以是在敘事提交與投遞之前，由敘事導出義務。偵測是詞彙式的，敘事呈現了事件卻沒寫出規則點名的東西（或規則只是暗示原因）就抓不到，規則若寫在該回合沒拿到的依據之外也看不到。只對行動的調查員扣除；「所有看見的人」不會被展開。被另一個待處理檢定擋下的檢定會釋放，不會排隊。以上都沒有對真實的 Camp Sunny 劇本或模型跑過。
