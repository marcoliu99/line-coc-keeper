# 敵人照數值表上的攻擊出手、因武器名稱暫停的宣告可以更正重來

[English](enemy_block_attacks_weapon_retry_design_spec.md)

狀態：**已實作**。基底：`main_v2` `b0c11f3`。

## 問題

來自 b0c11f3 的 2026-10-12 soak：

- **敵人從不出手。** Camp Sunny rerun6：Billy 的數值表寫了 Fighting 70%、傷害 8D6，但登記時沒有引擎能用的攻擊，最可能是只帶了「吞噬」能力。這樣能通過登記檢查，但他的回合只被敘述後讓出；已進行的那一輪他一次都沒攻擊。
- **一個武器名稱讓戰鬥停擺。** Lightless rerun3 第 50 輪：Beatrice 的鬥毆用了 `resolve_weapon` 對不上的名稱，還沒擲骰戰鬥就進入「需要裁定」。模型隨後查到了武器，但裁定還在，什麼都不能宣告；玩家讀到「這次行動尚未完整處理…工具失敗了」。

## 改動

- **攻擊取自數值表。** `initialize_combat` 或 `add_npc_to_combat` 登記非盟友敵人時，若沒有完整的攻擊（技能值與傷害），`support.attacks_from_stat_block` 會讀劇本數值表上寫成「<名稱> NN% … damage <骰>」的攻擊並登記。
  - 傷害裡的 DB 取數值表自己的 DB 那行；數值表沒寫加值的攻擊就不收。
  - 閃避不算攻擊。
  - 守密人自己給的攻擊照原樣保留；數值表沒有這樣寫攻擊時，既有的拒絕照樣要求補上。
- **更正後的宣告取代被暫停的那個。** 未知武器仍會進入裁定，因為劇本特有的武器要靠裁定補上定義。但同一位行動者再次宣告時，若唯一未完成的行動是他自己那個還沒擲骰、等待裁定的攻擊，就撤掉被暫停的行動，讓新的宣告繼續；用同一個 action id 或新的都可以。守密人仍想裁定時，照舊用 `resolve_combat_ruling`。

## 驗證

`tests/test_combat_state_machine_integration.py`：
- 只帶能力登記的敵人會拿到數值表上的 Fighting 70%／8D6 攻擊；
- 因未知武器名稱而暫停的宣告，可以被更正後的宣告取代（同一個 action id 或新的），且沒有擲任何骰。
