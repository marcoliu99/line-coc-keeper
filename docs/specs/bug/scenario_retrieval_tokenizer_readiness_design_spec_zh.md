## 問題與證據

2026-09-27 玩家要求拿取預付款、鑰匙並查看地址，26.76 秒後收到未完成訊息，裁決碼為 `invalid_evidence_reference`。紀錄包含三次成功檢索、六次工具嘗試，但沒有保留另外三次工具名稱與原始裁決引用，不能斷言其具體內容。

部署環境缺少 requirements.txt 已宣告的 `tiktoken`。程式以 UTF-8 位元組保守估算，Executor 輸入估計 65,865，超過設定的 32,000 上限，中文檢索預算因此為零。中文必要依據完全未送入模型；英文補查命中但完整性未知，不能直接證明缺少的中文關聯均已補齊。工具閘門在一般記錄流程之前拒絕機制操作，最終被通用未完成訊息掩蓋。

唯讀狀態確認背包／帳本沒有新增鑰匙與預付款，也沒有待處理檢定或 Luck。開場敘事已描述收到物品，卻沒有對應入帳；不可自動重播或直接修改正式存檔。

## 修正範圍

1. 補齊部署環境缺少的 tokenizer，確認編碼可載入，保留保守後備與預算上限。
2. 初始化 tokenizer 失敗時記錄原因類型，不記錄例外內容、提示詞或憑證。
3. 記錄檢索輸入估計、保留量、可用預算與實際計量方式。已知模型若退回位元組，投影資訊也必須如實顯示。
4. 依據／更正閘門擋下的工具仍須留下事實與診斷，不執行底層工具，不放寬既有裁決與狀態驗證。
5. 未完成且確有依據不足的工具拒絕時，明確說明缺少劇本依據，保留部分變更與檢定保護，不要求玩家為系統問題更正宣告。

不改資料結構、不增加固定 LLM 往返、不編造地址、不把任意英文命中視為完整、不修改正式遊戲狀態。

## 流程

    載入編碼 -> 估算輸入與保留量 -> 分配檢索預算
       | 失敗：保守位元組估計並記錄診斷
    中文依據 -> 完整性閘門 -> 執行工具／記錄拒絕
    裁決交接 -> 既有真實狀態驗證 -> 安全且說明原因的回覆

## 驗證

- 缺 tokenizer：保守計量、診斷與投影資訊正確。
- 離線重建事故兩組中文根節點，對照編碼可用與零預算結果。
- 被拒工具不修改狀態，但會留事實與診斷；無關英文命中不能解鎖。
- 相符完整依據能放行真實背包操作與裁決，模型使用測試替身。
- 未完成回覆維持已提交變更、檢定保護，說明依據不足。
- 執行隔離全套測試、lint 與型別檢查，不呼叫付費模型。

## 限制

離線測試能驗證檢索、閘門、入袋與交接，不能保證真實模型下一輪選擇相同工具。命中講義沒有具體門牌，不應補造。現有 bot 已快取 tokenizer 不可用，需由使用者重新啟動。
