# 戰鬥回合一定能結束

[English](combat_turn_always_endable_design_spec.md) | [Docs index](../../README.md)

類別：`bug`。狀態：**implemented**。基準：`main_v2` 的 `37e16bd`。

## 問題

《The Haunting》四人實跑（300 回合只跑到 155）在第 143–155 回合卡在戰鬥裡：

- 第 143 回合：玩家只是爬進爬行空間，守密人卻在還沒有敵人時呼叫 `start_combat`。先攻輪到一位調查員（soak-D），其他玩家連續五回合（145–150）被回「請先等待[未填]完成目前的行動」。被等的人這時做的是探索，不是戰鬥行動，先攻永遠不會前進；而且訊息寫的是 `[未填]`（四張角色卡的名字都是空白），沒人看得出該等誰。
- 第 148 回合：守密人嘗試 `close_legacy_combat` 與 `add_npc_to_combat`，有一個工具失敗，老鼠群到這時才加入。
- 第 151–155 回合：目前行動的調查員依序嘗試護住自己、踢、用木板打、躲到掩護後、撤退，每次都得到「這個行動無法進行」；戰鬥一直停在第 1 輪、READY，沒有攻擊、傷害或結算。

引擎只認攻擊：`declare_combat_action` 需要武器，`advance_combat_turn`（`combat_flow.advance_combat`）要求目前行動者在本輪已有一個「完成的行動」才肯前進。不攻擊、或行動沒有對應工具（護住自己、躲藏、撤退、劇本自創的行動）的玩家就結束不了回合，後面的人也跟著卡住。至於 Executor 當時該不該嘗試「踢」（`kick` 是武器表徒手的別名，在乾淨狀態下可以正常宣告），實跑記錄不足以判定，不在這次修改範圍。

## 修改

`advance_combat_turn` 多一個選用的 `skip` 旗標。`skip=true` 且沒有未結算的項目時，目前行動者的回合會被記為已執行（本輪一個已完成、不涉及規則的行動：不擲骰、不改任何資源），然後先攻照原本方式前進，包含接著開始下一個敵人的回合。不帶 `skip` 時完全不變。有未結算的行動或互動時拒絕略過，也只有目前行動者能略過。守密人提示加一句：戰鬥中沒有對應機制的行動（護住自己、躲到掩護後、撤退）要敘述後用 `skip=true` 結束回合，不要回答「無法進行」。

## 不做

- 開戰時連同敵人一起登錄，是 [bug-active-enemy-registration-after-combat-start](bug-active-enemy-registration-after-combat-start_zh.md) 與 PR #148 的主題；沒有敵人的戰鬥在關閉前仍會扣住整桌人。
- 等待訊息仍用角色名，所以四張沒有名字的角色卡都顯示 `[未填]`。
- 不做閃避、反擊、逃跑或追逐規則，也不做計時。
- 第 151–155 回合 Executor 為什麼沒有任何工具呼叫還沒有答案：第 151 回合前的 `/coc combat status` 顯示是正常的 managed 戰鬥（第一位調查員行動中、鼠群在場），乾淨的測試狀態也能正常宣告 `kick`。那次實跑的四張角色卡都沒有名字，真實角色卡不會這樣；先用有名字的角色重跑，再判斷是不是缺陷。

## 測試

`tests/test_combat_skip_turn.py`：不帶 `skip` 時照舊被拒絕；帶 `skip` 時先攻前進；有未結算行動時、或非目前行動者略過時被拒絕。
