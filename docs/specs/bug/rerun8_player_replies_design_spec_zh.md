# 一場 Codex run 裡的四種回覆：被拒絕後放棄、開戰場景被吞掉、Luck 提示講三次、戰鬥結束後還被拒絕

[English](rerun8_player_replies_design_spec.md)

狀態：**已實作**。基底：`main_v2` 的 `a4ef873`。

## 問題

2026-10-10 在 `05cbbb2` 上跑的四人《鬼屋》run（Codex `gpt-6-luna`，200 回合，自動擲骰開啟）每回合都完成了，但有四種回覆讓玩家讀起來不對：

| 回合 | 玩家看到 | 原因 |
|---|---|---|
| 3 | 「處理這個行動的工具失敗了」 | 劇本寫「擲 1D100 與 APP 或信用評級比較」決定 Dooley 的反應。`roll_dice` 擋下公開的 1D100，並說明改用 `skill_check` 或暗骰（`d100_against_a_characteristic_is_a_check_design_spec`）。守密人卻直接以 `incomplete` 結束。`model_incomplete` 的結論從來拿不到同一段對話裡的重試，所以拒絕訊息裡的做法沒被用上。另一輪遇到同樣的拒絕，照做就成功了。 |
| 33 | 只有「你的這次行動尚未執行，請先等待George Finch完成目前的行動」 | Clara 這句開啟了戰鬥，但先攻是 George 先，所以她的攻擊是 `deferred`。敘事者其實寫了 Corbitt 復活，但 `enforce_mechanic_check_consistency` 把所有 `deferred` 的回覆都換成等待句。 |
| 4、34–55 及多數檢定 | Luck 選項出現兩三次，最後還有「既有骰值 86 仍等待 Luck 決定…；不要重擲」 | 敘事提一次 Luck；敘事裡沒有 `/coc luck` 時，`_pending_luck_instruction` 再補一次指令清單；最後送出時又加上一行自己的 Luck 提示。玩家根本沒重擲，「不要重擲」聽起來像責備。自動擲骰時，`skill_check` 的收據還會在等待 Luck 的同時寫「…的檢定已結算：骰值 93」。第 44 輪還出現「`:luck`」：id 清理只拿掉 `check-<hex>`，留下了 `:luck` 後綴。 |
| 56 | 「這次行動目前無法繼續…依目前的劇本與場景狀態，這個行動無法進行；請改試別的做法。」 | 敵人已經 HP 0。守密人確認了戰鬥結算並擋下這次攻擊，回覆卻用了通用的 fallback。 |

## 變更

- **被拒絕後再給一次機會。** Executor 的 `final_feedback` 裡，`model_incomplete` 的結論在下列情況下可以用掉既有的那一次重試：這回合失敗的呼叫都只是拒絕、沒有寫入狀態，成功的呼叫都是查詢（`INFORMATION_QUERY_TOOLS`）。提示會說明拒絕訊息已指出該用的工具或參數，請照做；確實做不到才保留 `incomplete` 並說明原因。有寫入狀態的拒絕不算，例如等待裁定而暫停的戰鬥行動。codex provider 本來就限制每段對話只重試一次。
- **開戰那句保留場景。** `deferred` 的回合只能透過設置戰鬥改變狀態（`turn_resolution._setup_only`）。若這回合確實設置了戰鬥（`state_changed`），回覆就是敘事加上等待句；單純的延後仍只有等待句。
- **Luck 只講一次。** 送出時的 Luck 提示改為「骰值 86 還在等 Luck 決定：請按 Luck 按鈕，或輸入 /coc luck skip 保留原結果。」若回覆已經含有 `/coc luck` 和這個骰值，就不再加這一行。Luck 決定還沒做時，不顯示 `skill_check` 收據的「已結算」那一行，因為 Luck 提示已經寫了骰值。id 清理會連同 `:luck` 後綴和程式碼引號一起移除，並整理句尾標點前殘留的冒號。
- **戰鬥結束後才出手。** 回合被擋下，而且這回合確認了戰鬥結算、目前已沒有戰鬥，且還有人站著時，回覆「戰鬥已經結束，這一擊不必再出手了。接下來想做什麼？」。

## 不變更

- 發生錯誤後的 fallback 仍保留「不要重擲」：那種時候重做行動確實有風險。
- 敘事者仍可以用自己的話提到 Luck 花費；重點是指令清單不再重複。

## 驗證

`tests/test_rerun8_player_facing.py`：
- 查詢後被拒絕可以重試；沒有拒絕、有成功寫入、或拒絕本身寫了狀態，都不重試。
- 設置了戰鬥的延後回合保留敘事加等待句；單純延後只有等待句。
- 回覆已有指令和骰值時不再補 Luck 提示，提示裡也沒有「不要重擲」；等待 Luck 的骰不寫「已結算」；包在程式碼引號裡的 `check-<hex>:luck` 會被乾淨移除。
- 確認了結算後被擋下的回合，會說明戰鬥已經結束；全隊倒下時不這樣回。
