# PDF publication policy verification

The publication policy is implemented on PR155's `enhancement/pdf-multicolumn-ingestion`. A source-safe scenario with an invalid, incomplete, missing or failed map publishes with warnings; the unsafe Map Engine feature remains disabled. Source failures still block. No provider image uploads were needed for this policy verification.

1. **Files changed:** production changes in `app/pdf_loader.py`, `app/pdf_ingestion_drafts.py`, `app/scenario_library.py`, `app/legacy_commands.py`; new `tests/test_pdf_publication_policy.py`; updated map/source regressions, bilingual specs and catalog. Activation and movement code are unchanged.
2. **Old/new disposition:** before, an unverified map was directly included in `failed_graphic` / needs_review. Now source-only failures determine source disposition, while map status is recorded separately in derived_feature_warnings and publication_severity. Safe source remains accepted/legacy_route, even when the map fails. Pipeline identity is multicolumn-v7; OCR and map certificate versions are unchanged.
3. **HARD_BLOCK:** unsafe source ordering, required image-only source without authoritative verification, unresolved source mechanics, unverified source transcription, or entirely missing playable source. A verified graph does not establish authoritative transcription. HARD_BLOCK takes precedence when a source defect and map warning coexist. blocked_pages equals hard_block_pages.
4. **SOFT_REVIEW:** source-safe map failure (including unavailable provider/audit/budget, missing entry, invalid/incomplete graph and unsuccessful repair), plus other non-blocking review diagnostics. Reports expose READY / READY_WITH_WARNINGS / BLOCKED, soft_review_pages, hard_block_pages and map_status. A positively verified text-free illustration still needs no authoritative OCR; unknown image content remains conservatively source-blocking.
5. **Draft/resume:** accepted/legacy_route/soft_review-compatible pages resume only under matching source/hash/extraction identity, with no hard source reason. A missing optional graph no longer forces redispatch; unsafe graph candidates are not returned as reusable maps. Attached gameplay graphs retain certificate checks. Private graph provenance survives successful publication in `.ingestion-provenance.json` (0600); sanitized parse_quality.json retains warning/status/error/hash/timing metadata without graph candidates/provider responses.
6. **Map publication regressions:** invalid, incomplete, missing, provider-failed and audit-failed maps all publish safe source with READY_WITH_WARNINGS and no library map. Budget-exhausted map analysis is non-blocking. Existing certificate-tampering rejection remains tested. Soft pages resume without another provider call; the soft_review compatibility alias also passes.
7. **Hard-source regressions:** image-only character-sheet numeric disagreement remains unverified and BLOCKED, with no library publication. Unresolved STR source plus invalid map is HARD_BLOCK for source reasons. Entirely blank source is a reported hard block. Existing numeric/dice/percentage acceptance and conflict tests remain intact.
8. **First upload/start:** a real synthetic PDF with 30 safe narrative pages and one invalid floor-plan graph passes the actual handle_pdf_upload path, real SQLite/library persistence and activation, and the existing /coc start command with an investigator. scenario_library_id and source text are available; both scene_maps.json and state.scene_maps exclude the graph. Success says the map feature is disabled and the scenario can start; no Continue loop is requested. Deferred confirmation retains the same warning data.
9. **Checks:** full pytest 2051 passed, 2 skipped (9 existing dependency deprecation warnings); Ruff passed; mypy passed in 132 source files; python -m compileall app tests passed; git diff --check passed. Integration branch alignment was checked against fetched main_v2.
10. **Remaining blockers:** none for this publication-policy change. Prior real Haunting/Beacon graph correctness and real image-only authoritative-positive evidence remain pending; no result is fabricated, and unverified maps stay disabled. These pending derived-map results do not block otherwise safe scenario publication under the new policy.

They are not correctness failures; independent hash/certificate checks remain at each boundary.
