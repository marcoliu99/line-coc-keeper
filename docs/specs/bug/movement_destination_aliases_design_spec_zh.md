# 由 AI 裁定移動目的地名稱

## 問題與目標

2026-09-28 16:05 的日誌顯示：「我去圖書館」→「中央圖書館」與「我去老屋」→「科比特宅邸」都被 `movement_destination_mismatch` 擋下；當回合已找到 Central Library 與 Corbitt House 的劇本段落。把目的地改成玩家原詞「圖書館」再測，則因英文來源不含中文字而得到 `destination_not_supported_by_evidence`。兩次都在路徑驗證前卡於字面比對。PR #99 加入嚴格抵達檢查，PR #121 放寬 OCR 地圖連線，但仍保留這兩道名稱檢查。

目標是讓**現有 Executor** 判斷目的地是否就是玩家想去的地方，以及當回合劇本依據是否支持它。管理員可切換這個行為；不增加 LLM 呼叫、翻譯步驟、別名查表、模糊分數或地圖重建。

## 決策與範圍

- 在 `app/config.py` 與 `.env.example` 加入 `MOVEMENT_DESTINATION_MATCH_MODE=strict|ai`。預設 `strict` 以維持相容；未知值在設定驗證時拒絕。管理員設定 `ai` 並重啟 bot 後啟用。
- `ai` 模式的 `commit_movement` 只跳過兩道目的地名稱檢查：`movement_destination_mismatch` 與 `destination_not_supported_by_evidence`。Executor 仍須提交目的地、玩家 `source_span`、當回合證據引用及清楚／待檢定／受阻條件。Python 繼續核對 PR #121 既有的來源身分與引文規則，但不再嘗試以字串證明目的地與玩家或來源文字語意等價。
- 其他檢查全部保留：玩家當回合原句授權、第三方／OOC／否定排除、待處理檢定與 Luck 身分、明確阻礙、鎖門、必要檢定、反應點、戰鬥限制、地圖歧義，以及先抵達再處理目的地效果。玩家只是提到或詢問地點不得移動。
- 地圖仍依 PR #121 作為位置輔助；缺少地圖頁或 OCR 邊線不會變成合法轉場的必要條件。敘事不能補造中途房間或事件。
- 不增加工具欄位或固定 LLM 階段。沿用同一次 Executor 工具呼叫的裁定；Python 保留規則及狀態檢查，只在有長度限制的診斷事件記錄模式與目的地，不記提示詞或完整檢索段落。
- 其他檢查若擋下移動，須回傳明確原因，不得全部折成「行動尚未完整處理」。

## 不包含與明確取捨

- 此模式不關掉 PR #99 全部檢查，只放寬本次日誌觸發的兩道名稱／相關性檢查。
- `ai` 模式下，Python 無法獨立證明「老屋」等於「科比特宅邸」，也無法證明引用段落真的支持該目的地；現有 Executor 可能判錯。這是管理員為避免額外分析與錯誤拒絕而選擇的取捨，可切回 `strict`。
- 中文 RAG 版本是每團獨立選擇；既有 `/coc scenario use <劇本ID> <已核准版本ID>` 可切換。日誌的 `requested_variant=original` 表示該團使用原文。單切中文 RAG 不能解決玩家用詞與模型目的地不同的第一道錯誤。
- 不遷移存檔、不重新匯入劇本、不背景翻譯、不加逐回合審稿，也不改劇本正典提示詞。

## 流程

```text
玩家當回合行動 -> 既有 Executor 與當回合 RAG
      -> commit_movement(目的地、玩家原句、證據、條件)
      -> 核對玩家行動授權、待決事項及障礙
      -> 核對證據來源與引文
      -> strict：既有目的地名稱／相關性檢查
         ai：接受 Executor 的目的地裁定
      -> 既有地圖／場景解析及阻礙檢查
      -> 抵達後才處理目的地相關效果
```

## 測試與驗收

- 在真正的 `commit_movement` 接口重現兩筆日誌。`strict` 維持既有拒絕碼；`ai` 用相同工具參數及當回合證據成功抵達 Central Library、Corbitt House，並確認沒有增加 provider 請求。
- 兩種模式都必須拒絕無效／過期來源 ID、無效的非 RAG 引文、沒有玩家移動授權、提問／假設／否定／OOC／第三方移動、待檢定／Luck、鎖門、必要檢定、反應點與歧義地圖。拒絕時位置不變。
- OCR 地圖缺線時的合法轉場仍成功；明確的房間障礙不會因開關而被繞過。
- 測設定預設值、解析與未知值；`.env.example` 寫出實際設定。執行移動／Executor 重點測試、ruff、mypy 與完整測試。

## 實作時待注意

目前 `destination_not_supported_by_evidence` 在 `strict` 模式也阻止任意未知地點；改為 `ai` 後，語意相關性由 Executor 負責。保留來源驗證與可追查的診斷，但不要偷偷加入另一套別名或相似度檢查，否則開關仍會擋下同樣的回合。
