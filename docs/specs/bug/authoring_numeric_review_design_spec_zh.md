# 外部整備數值校對

狀態：使用者提供的 CLI 任務已授權實作（2026-09-27）。

## 問題與範圍

匯出指引未說明兩種不同的數值契約；核准只顯示前三項，掩蓋後續紀錄。
舊 PDF 擷取可能將雙欄、頁腳、側邊裝飾與機制混排。數值清單不能證明翻譯
忠實，也無法自行判斷來源數字的意義。

本次更新未來工作檔、共用數值解析、逐欄診斷與私密核准報告。保留既有匯出
登錄及正式草稿；不自動翻譯、不提供數值豁免、不增加遊戲 API 呼叫。
私密劇本內容與修正草稿不提交儲存庫。

## 契約

* 每個規則欄位，中文數值 Counter 必須符合唯一精確來源引述，含重複次數與
  引述中的參考頁碼。
* 每筆來源數值集合須出現在該筆 public/kp 正文或結構化規則中文。名稱、別名、
  關鍵字、引述、uncertainty 或其他紀錄均不能代替。
* 支援數字緊鄰中文；骰式大小寫及加減修正值旁的水平空白視為相同格式。
  數值、次數、百分比、小數寫法仍嚴格比對，不猜中文數字的對應。
* 收集所有獨立欄位錯誤。核准重新驗證每筆，產出含缺失數值及原文上下文的
  私密報告。完整報告不截斷；僅例外摘要有上限。
* 若唯一差異是百分號表示（去掉百分號後數值及次數相同），可儲存為明確的
  待校對草稿，使不同包可逐次更正；核准仍拒絕所有這類疑點。真正數值或次數
  不符仍拒絕匯入，沒有數值豁免。
* 匯入成功不等於核准。首次提交不列 replacement IDs；更正時只列該批次中
  已存在且本次有提交的紀錄 ID。

## 來源修復與人工校對

報告是校對工作表，並非刪除來源的許可。須記錄來源 hash、來源 ID／範圍、
擷取原句、PDF 實體頁／裁圖、修正文句、分類、原因、校對者及日期。分辨：
(1) 漏譯、(2) 跨單元移動、(3) 有意義的參考頁碼、(4) 版面雜訊、
(5) 損壞數值、(6) 不確定的圖片描述／角色卡。

(1)-(3) 在各單元忠實翻譯完整有意義的段落，必要時加依賴，不貼裸數字清單。
(4)-(6) 對照 PDF，製作附稽核紀錄的重新擷取候選，先封存原始來源與草稿。
透過既有劇本匯入／重解析流程處理 PDF，核對 parse_quality 與工作表才使用。
來源／章節 hash 改變後重新匯出，將譯文重新綁定新單元及引述。
重解析本身不代表修復成功；若錯誤仍在，維持未核准，等待經校對的解析器／
來源修正。不原地修改登錄，也不接受上傳 ignore_numbers 豁免。

現有 PDF 解析器已有分欄及證據／品質警告。本次不加入猜測性的頁腳刪除，
不執行正式來源遷移。提供的 19 筆草稿仍需來源校對，包括地圖與角色卡。

## 流程

    匯出 + 字面數值清單（不是修復指令）
      -> 外部完整翻譯 + 數值自查
      -> 首次匯入 / 明確取代已存在紀錄
      -> 來源綁定 + 逐欄 Counter + 逐筆覆蓋
      -> 核准重新檢查全部紀錄
           -> 無疑點：記錄校對者並核准
           -> 有疑點：完整私密報告 + 來源修復工作表
                -> 譯文修正：同一匯出、明確列 replacement IDs
                -> 來源修復：校對擷取結果、新匯出、重新綁定

## 驗證

合成案例涵蓋真實匯出／匯入／核准、重複數值、骰式空白、中文數字／相鄰文字、
多餘頁碼、排除 metadata、版面雜訊、超過三筆紀錄、超過摘要上限的完整報告，
以及首次與更正匯入。另以本機 r1-r19 草稿、不可變登錄及原 PDF 做完整稽核，
明確列出仍未解決的項目。

## 後續：可執行的來源修復（2026-09-27 已授權）

新增管理用 CLI：`python3 -m app.scenario_source_review`，提供 `prepare`、
`check`、`publish`、`rebind`。這是整備操作，不是玩家行動或背景自動翻譯，
不使用付費 API。

* prepare 在私密伺服器登錄封存來源／PDF／章節身分，匯出每個實體頁的圖片、
  舊擷取與本機原生擷取候選，以及可編輯的 Markdown JSON 提案。
* 每頁填寫正文、校對說明與 PDF 證據矩形。缺文字、說明或證據時不能發布。
  點陣圖片頁需轉錄，原生擷取候選不等於內容完整。純圖片頁可明確標為
  image_only，保留圖片連結與校對說明，不編造空間描述。
* check 列出修正前後完整數值次數及涵蓋提案與可信來源身分的 digest；不套用。
* publish 須由操作者提供校對者與已檢查的 digest，重新確認來源／PDF／章節，
  原子建立新劇本 ID。保留舊來源、匯出與目前遊戲選擇；稽核保存每頁修正前後、
  證據、數值差異與校對者。來源衍生索引、角色卡物件、推測地圖失效；原 PDF
  與頁面圖片保留，衍生物件另行重建。發布來源不代表中文模板通過核准。
* rebind 建立新整備匯出；只有單一來源單元、全文完全相同且唯一對應的既有
  紀錄可重用。重新編譯引述，重設來源／紀錄／單元 ID，不帶舊關聯 ID。
  有關聯或依賴者僅列人工參考，不自動拆掉規則關聯。變更／歧義／多單元紀錄
  放私密遷移報告，新紀錄保留待翻譯標記；不自動匯入或核准，只修改成果副本。
* 測試涵蓋過期／損壞快照、提案變更、漏頁、邊界與證據、數值稽核、新來源
  發布重試、原始與遊戲資料不被覆寫，以及保守的譯文重新綁定。

    prepare -> 頁面圖片 + 提案
      -> 逐頁對照 PDF -> check + digest
      -> publish(校對者, digest) -> 新劇本 + 稽核
      -> rebind(舊匯出) -> 新工作檔 + 可重用成果草稿 + 報告
      -> 正常匯入 -> 完整數值校對 -> 明確核准模板
