# 外部整備數值校對

狀態：使用者提供的 CLI 任務已授權實作（2026-09-27）。

## 問題與範圍

匯出指引未說明兩種不同的數值契約；核准只顯示前三項，掩蓋後續紀錄。
舊 PDF 擷取可能將雙欄、頁腳、側邊裝飾與機制混排。數值清單不能證明翻譯
忠實，也無法自行判斷來源數字的意義。

本次更新未來工作檔、共用數值解析、逐欄診斷與私密核准報告。保留既有匯出
登錄及正式草稿；不自動翻譯、不提供數值豁免、不增加遊戲 API 呼叫。
私密劇本內容與修正草稿不提交儲存庫。

## 契約

* 每個規則欄位，中文數值 Counter 必須符合唯一精確來源引述，含重複次數與
  引述中的參考頁碼。
* 每筆來源數值集合須出現在該筆 public/kp 正文或結構化規則中文。名稱、別名、
  關鍵字、引述、uncertainty 或其他紀錄均不能代替。
* 支援數字緊鄰中文；骰式大小寫及加減修正值旁的水平空白視為相同格式。
  數值、次數、百分比、小數寫法仍嚴格比對，不猜中文數字的對應。
* 收集所有獨立欄位錯誤。核准重新驗證每筆，產出含缺失數值及原文上下文的
  私密報告。完整報告不截斷；僅例外摘要有上限。
* 匯入成功不等於核准。首次提交不列 replacement IDs；更正時只列該批次中
  已存在且本次有提交的紀錄 ID。

## 來源修復與人工校對

報告是校對工作表，並非刪除來源的許可。須記錄來源 hash、來源 ID／範圍、
擷取原句、PDF 實體頁／裁圖、修正文句、分類、原因、校對者及日期。分辨：
(1) 漏譯、(2) 跨單元移動、(3) 有意義的參考頁碼、(4) 版面雜訊、
(5) 損壞數值、(6) 不確定的圖片描述／角色卡。

(1)-(3) 在各單元忠實翻譯完整有意義的段落，必要時加依賴，不貼裸數字清單。
(4)-(6) 對照 PDF，製作附稽核紀錄的重新擷取候選，先封存原始來源與草稿。
透過既有劇本匯入／重解析流程處理 PDF，核對 parse_quality 與工作表才使用。
來源／章節 hash 改變後重新匯出，將譯文重新綁定新單元及引述。
重解析本身不代表修復成功；若錯誤仍在，維持未核准，等待經校對的解析器／
來源修正。不原地修改登錄，也不接受上傳 ignore_numbers 豁免。

現有 PDF 解析器已有分欄及證據／品質警告。本次不加入猜測性的頁腳刪除，
不執行正式來源遷移。提供的 19 筆草稿仍需來源校對，包括地圖與角色卡。

## 流程

    匯出 + 字面数值清單（不是修復指令）
      -> 外部完整翻譯 + 數值自查
      -> 首次匯入 / 明確取代已存在紀錄
      -> 來源綁定 + 逐欄 Counter + 逐筆覆蓋
      -> 核准重新檢查全部紀錄
           -> 無疑點：記錄校對者並核准
           -> 有疑點：完整私密報告 + 來源修復工作表
                -> 譯文修正：同一匯出、明確列 replacement IDs
                -> 來源修復：校對擷取結果、新匯出、重新綁定

## 驗證

合成案例涵蓋真實匯出／匯入／核准、重複數值、骰式空白、中文數字／相鄰文字、
多餘頁碼、排除 metadata、版面雜訊、超過三筆紀錄、超過摘要上限的完整報告，
以及首次與更正匯入。另以本機 r1-r19 草稿、不可變登錄及原 PDF 做完整稽核，
明確列出仍未解決的項目。
