# 劇情行動與檢定交接

狀態：已同意實作。基底：main_v2。分支：bug/scenario-action-check-handoff。

## 事故

兩則相隔九秒的訊息，以錯字更正重述同一拾取動作。第一筆耗時 67 秒、搜尋六次並建立一筆檢定；第二筆仍為未變動的檢定跑完 Executor／Narrator。劇本區分拾起物件、握住物件與抓取飛行物件，但採用的檢定屬於不同條件；另外擲出的 NPC 骰果也沒有綁入玩家檢定。中文來源已含被引用規則，卻沒有依賴連線。

## 契約

- 玩家原始宣告與模型行動解讀分開保留。檢定可帶有受限的 action basis（物件狀態、適用規則引用與轉變），它是解讀，不是新正典。提示詞要求遵循最具體且已成立的觸發條件，不能代選玩家未宣告的防禦戰技；不寫死劇本名稱。
- skill_check 新增選填對抗契約：對手能力與數值、明確平手勝方（玩家／對手／都未勝）、來源與有限的勝敗後果。程式先確認 pending／Luck／防重複，再擲一次對手骰並持久保存；模型不能提供骰果。Python 比較成功等級，雙方失敗不能視為成功。契約與原始行動隨 pending、Luck、正式事件及敘事交接；後果代表適用分支，機制變更仍須既有工具。公開提示不暴露對手隱藏數值或來源。自動擲骰與手動共用比較，Luck 不重擲任何一方。
- 只有通過驗證的 await_check／await_luck 仍指向同一擁有者、檢定／決定、時間線，且無遊戲狀態變更及新的工具／輸出效果，才略過 Narrator，回簡短提醒並正常寫入回合紀錄。不能用模糊文字比對丟棄訊息；取消、更正與獨立行動仍進 Executor。
- 外部整備工作檔要求跨頁依賴。只有來源中的具名引用能唯一對上來源標題時，才以確定性規則補必要關聯，不以關鍵字或鄰頁猜測。先對完整紀錄解析，再套用章節權限；必要目標不在權限內仍須阻擋。未知／歧義引用列診斷，交外部整備釐清，不編造目標。保留全文與數值檢查。舊核准紀錄可在記憶體衍生關聯，不改寫原核准檔案。

## 流程

```text
玩家宣告＋目前狀態＋劇本必要關聯
 -> Executor 選擇適用條件與工具
 -> skill_check 保存行動依據＋對手骰果
 -> 等玩家擲骰 -> 可選 Luck
 -> Python 比較等級／平手 -> 權威事件 -> Narrator

Executor 仍等待同筆舊檢定、沒有新效果
 -> 固定待擲提醒 -> 正常保存歷史（不呼叫 Narrator）

來源具名引用 -> 唯一來源標題 -> 必要關聯
 -> 章節授權投影 -> 完整依據／保守阻擋
```

## 驗證與限制

離線測試涵蓋舊檢定提醒、新／改動檢定與副作用；對抗勝敗、平手、雙失敗、防重複、Luck 維持／花費、自動擲骰與重載；自由理由不洩漏；跨頁引用、歧義、章節邊界與來源檔案不變。須通過完整測試、Ruff、mypy。不新增付費 LLM 階段、不重播正式遊戲、不重擲或修補玩家狀態。規則選擇仍是 AI 解讀，結構化依據讓它可查核，但不能證明語意一定正確。
