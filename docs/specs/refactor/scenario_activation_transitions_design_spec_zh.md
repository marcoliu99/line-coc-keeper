# 劇本啟動與章節轉換

[English](scenario_activation_transitions_design_spec.md)

狀態：**implemented**。基準：`main_v2` 的 `07d55a7`。

## 目前行為

首次 PDF 上傳、上傳選擇、`/coc scenario use`、章節推進與檢查點回溯都會安裝劇本 Context 或重建頁面圖片。前四條路徑目前在權威 SQLite 提交前刷新衍生圖片，回溯則先提交。各路徑原有不同的時間線、地圖、預製角色卡、手動角色卡及位置政策。

## 介面

`app/scenario_activation.py` 負責 Context 欄位安裝，以及先提交 state、再發布圖片的順序。呼叫端提供既有的 SQLite 提交函式、變體與保留政策、以及 Context；模組回傳衍生圖片快取是否刷新成功。提交後圖片失敗只回報刷新失敗，不會宣稱 state 轉換失敗或要求重做。提交失敗時不發布圖片。提交成功後，共用發布器先使前劇本頁面快取失效，再讀取所選章節圖片；若來源複製失敗，相同頁碼不會讀到舊圖片或僅暫存的部分新圖片。回溯可容許歷史劇本庫項目已遺失。

轉換專屬政策在各呼叫端明確保留：全新上傳與修正、劇本庫選擇、章節推進及回溯仍使用原本的狀態重置、手動角色卡交易、變體選擇、位置與地圖規則及收據。不建立新資料庫 adapter。權威邊界仍是實際 SQLite 與檔案系統圖片。

## 驗證

以實際暫存 SQLite 資料庫與圖片目錄測每種轉換的提交失敗及圖片失敗。確認提交失敗時 state 不變，僅圖片失敗時 state 已提交，且提交成功前不發布舊頁面圖片。保留既有 state persistence 與手動角色卡測試，再執行完整 pytest、Ruff 0.16.8、mypy、compileall。
