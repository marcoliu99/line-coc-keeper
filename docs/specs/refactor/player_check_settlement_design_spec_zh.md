# 玩家檢定結算與安全續敘

[English](player_check_settlement_design_spec.md)

狀態：**backlog，待規格審查**。基準：2026-09-29 的 `main_v2`，commit `7cef87c`。

## 問題與目標

`app/check_lifecycle.py` 已負責 Keeper 工具*建立*待處理檢定時的准入與身分。另一半仍在 `app/legacy_commands.py`：`/coc check` 與 Luck 選擇取出 pending、只擲一次骰、套用 SAN／Luck 和對抗結果、儲存狀態、呼叫 Keeper 後續，最後發布 `resolved_check_event`。這段長流程跨越狀態鎖、敘事序列、工具執行與 Discord 傳送。目前確定的骰子先存檔，但 resolved event 要等 Keeper 回來才發布；後續失敗時可能留下已結算骰、卻沒有可持久續行的憑證。

目標是建立深模組，擁有玩家檢定與 Luck 的結算交易；骰子最終確定時記錄**待續敘結果**，並安全接續，不重擲、不重播已完成工具。

## 範圍與介面

- 文字指令與按鈕走同一結算介面。介面在既有狀態鎖內讀取最新狀態，核對玩家、檢定、Luck 決定和時間線身分，消耗或還原 pending，只做一次確定性的擲骰或 Luck 選擇，套用規則效果，並把結果與持久憑證一起提交。
- 待決定的 Luck **尚未**結算；只有最後的 Luck 選擇，或不需 Luck 的骰子，才建立待續敘結果。保留現有准入、autoroll、舊存檔身分後備、重傷 CON、對抗檢定，以及遠距攻擊方只擲一次等規則。
- 憑證記錄群組時間線、調查員的玩家與角色、檢定／Luck 身分、原行動、確定骰值與結果、受眾和續敘階段。同一群組至多一筆未解決憑證。存在時暫停全組新遊戲行動；查狀態、更正、原有權限允許的管理，以及專用續敘入口仍可使用。
- 後續失敗時顯示 `/coc resume` 與同功能按鈕。原玩家或已登記 KP 助手可觸發；訊息仍只送原本持久記錄的公開或私人受眾。續敘重新讀取權威狀態與憑證，絕不重新擲骰或花 Luck。
- Keeper 後續與 Discord 傳送留在確定性結算交易及狀態鎖外。外層編排使用憑證中的事實，不靠聊天摘要還原。系統產生的檢定後續文字不得送進玩家移動語句解析器。
- 若 Keeper 後續已執行其他工具才失敗，只能依可證明已記錄的工具結果和最新狀態安全接續；不可重播完成的工具。無法證明安全續行時，把憑證標為待人工處理並提供現有 `/coc correct` 途徑，不可宣稱完成。現有 mutation admission 與 turn resolution 保持權威。
- Keeper 後續完成後，原本的 `resolved_check_event` 恰好發布一次，狀態效果從已提交狀態歸因，私人受眾保持正確。若 Keeper 已完成但 Discord 傳送失敗，保留完成輸出或回報其狀態，不再呼叫 Keeper。通用的 Discord outbox／重啟傳送屬另一候選。
- 重開劇本或章節回溯換時間線時，舊憑證失效並留下稽核紀錄，解除全組暫停；新時間線不得重播舊骰子或敘事。

## 資料與相容性

在 `GroupState` 新增有上限、帶階段與身分的待續敘憑證欄位。最終骰子結果與初始憑證在**同一筆**既有狀態交易中提交；後續工具結果與完成輸出在重試引用前須以穩定身分記錄。若發生無法證明工具是否已執行的崩潰窗口，採保守暫停。`resolved_check_events` 仍只代表已完成的後續，避免更正裁決與既有讀取端把中間憑證當作公開事件。沒有新欄位的舊存檔視為空值；所有重置時間線與 pending 的路徑也要清除或註銷新欄位。

## 流程

```text
玩家按鈕或 /coc check / Luck 選擇
  → 狀態鎖＋最新身分核對
  → 確定性骰子或 Luck 選擇，只做一次
  → 原子提交狀態＋待續敘結果
  → 釋放狀態鎖
  → Keeper 根據已記錄事實處理後續
       │ 完成 → resolved_check_event 恰好發布一次 → 傳送
       │ 工具結果不明 → 暫停更正，不重播
       └ 安全完成前逾時 → /coc resume 或按鈕
  → 憑證未解決時，全組新遊戲行動等待
```

## 非目標

不在此建立新檢定，准入仍由 `check_lifecycle` 負責；不把 Discord transport 併入結算模組；不新增固定 LLM 審稿；不改玩家檢定規則；不在重試時重擲；不讓 KP 助手得到調查員身分；不實作 turn-safety 規格中的通用 outbox。

## 驗證

1. 文字與按鈕都測一般技能、SAN、選項、Luck skip／花費、autoroll、重傷 CON、近戰及遠距對抗。同身分重試不得重擲、再次花 Luck 或重擲遠距攻擊方。
2. 模擬結算提交後、Keeper 後續中、後續工具成功後、Keeper 輸出後，以及 Discord 傳送中失敗；各點都核對憑證階段、精確狀態效果與安全恢復／明確暫停。
3. KP 助手觸發續敘時，私人結果仍送持久記錄的收件人。全組遊戲動作暫停，但狀態、更正、授權管理和續敘可用。
4. 測回溯／重開失效、舊存檔、重複按續敘、多人並發、事件只發布一次，以及系統後續文字不進移動語句解析器。
5. 維持 `tests/test_check_lifecycle.py`、`tests/test_luck_buyup_gate.py`、`tests/test_pending_luck_short_circuit.py`、`tests/test_resolved_check_events.py`、`tests/test_npc_attack_latency.py`、`tests/test_turn_safety.py` 和按鈕路由測試通過。實作後跑完整 pytest、Ruff 0.16.8、`mypy app` 與 `python -m compileall app tests`。

## 取捨與審查決定

獨立憑證增加持久狀態，但保留「已完成檢定事件」的既有意思，並明確標出失敗窗口。全組暫停維持敘事順序；若沒有 KP 助手且原玩家離線，須等他回來續敘。Marco 已確認這些取捨、專用指令／按鈕、原玩家或 KP 助手的權限、時間線失效，以及部分工具結果無法證明時保守暫停。憑證的細部編碼可在遵守上述不變條件下於實作決定。規格審查前不改執行程式。
