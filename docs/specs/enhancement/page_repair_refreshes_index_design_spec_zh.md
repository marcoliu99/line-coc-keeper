# 頁面修復後自動更新索引，並指出被拿掉的數字

[English](page_repair_refreshes_index_design_spec.md)

狀態：**已實作**。基準：`main_v2` 的 `c6512c4`。來自 2026-10-14 對 `main_v2` 的稽核（劇本匯入）。

## 問題

`repair_*.md` 會整頁覆蓋目前劇本文字（`scenario_ingestion.handle_page_repair_upload`）。它有兩件事做得不如 PDF 上傳：

- 它不動 NPC／怪物與地點索引，還是原本 OCR 抽出來的版本。修頁面通常就是為了改正數值，但在有人手動執行 `/coc index` 之前，遊戲參考的不是改正後的內容，回覆也沒提這件事；
- 它照單全收，重新抽取那一頁的工具如果抄錯數字（`1D6` 變 `1D5`），就會一聲不響地進到劇本文字裡。

## 變更

修復存好之後，只要有被替換的頁面在目前載入的文字裡：

- 依修復後的文字重建索引，做法和 `/coc index` 一樣（同一個抽取、同一個編號地點不足的保護、合併地圖地點與詞彙），並告訴玩家索引現在有幾個 NPC 與地點。重抽的地點比文字裡的編號標題少時，保留舊索引並說明；任何失敗都保留舊索引與修復，並指向 `/coc index`；
- `scenario_page_repair.lost_numbers` 針對每個被替換的頁面，列出原頁有、新頁沒有的數字與骰式（`scenario_numbers.missing`），回覆中以警告列出（每頁最多六個、最多五頁）。它不會擋住修復：修正辨識錯誤的修復也會「少掉」那個錯的數字，沒有辦法分辨。

存給尚未載入章節的頁面在這裡什麼都不做（它們的文字還不在劇本裡）。第一則回覆不變，提示接在後面。

## 驗證

`tests/test_scenario_page_repair.py`：索引依修復後文字重建；重建失敗時保留修復與舊索引並說明；不完整的重建不寫入；給之後章節的頁面不重建；`1D6` 變成 `1D5` 時警告且保留修復；數字沒變、或頁面不在文字裡時沒有警告。這些測試在沒有這項變更時會失敗。
