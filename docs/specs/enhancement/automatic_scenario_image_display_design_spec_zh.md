# 可設定的劇本主動圖片展示

## 目標與已確認行為

設定 Keeper 主動展示劇本圖片時，要傳圖片或改成文字敘事。這是呈現選擇，不改變劇本事實、玩家發現、圖片匯入或地圖規則。

```dotenv
SCENARIO_IMAGE_DISPLAY_ENABLED=true
```

全站 `.env` 設定，預設 `true` 保留目前行為；啟動時讀取，修改後重啟 bot 生效。實作須同步 `.env.example` 與中英文 README，明確說明範圍。

| 請求 | true | false |
| --- | --- | --- |
| Keeper 主動展示公開圖片 | 已授權圖片 | 已授權文字敘事 |
| Keeper 主動展示私人圖片 | 傳給已解析的指定對象 | 文字傳給同一對象 |
| 玩家一般對話說「給我看圖片」 | 目前 Keeper 流程 | 文字；必要時提示 `/coc showpage` |
| 明確使用 `/coc showpage N` | 已授權原圖 | 已授權原圖 |
| 上傳 PDF／圖片、OCR、地圖、角色卡擷取 | 目前處理 | 目前處理 |

只有 `/coc showpage` 能略過附件抑制；模型自填旗標或一般自然語言不能略過。第一版不做各群組偏好或即時切換指令。

## 現況與缺口

- `app/keeper_tools/scenario.py:show_scenario_image` 核對目前章節脈絡的圖片與發話者權限，解析指定調查員，再排入圖片請求。
- `app/legacy_commands.py:_deliver_side_effects` 依請求公開或私訊送圖。私人檢定後續會把圖片／回覆 callback 改送原玩家私訊。
- `app/commands/handlers/map_handler.py:handle_map_command` 的 showpage 目前直接送圖，缺少工具路徑明確的圖片可見性检查。應共用授權政策，不能保留這個缺口。
- 圖片索引 description 目前只是整頁來源前 500 字，不是可直接公開的安全圖說。頁面原文、圖片描述與房間圖可提供脈絡，但仍須處理揭露與來源。
- 現有 prompt／工具描述承諾圖片，須依設定調整措辭，正確回報文字模式與手動看圖途徑。

## 介面與流程

建立主動工具與手動展示共用的呈現解析界面，集中圖片查詢、章節／可見性核對與圖片／文字選擇；明確保留發話者、受眾，不處理世界狀態變更。結果區分 `image`、`text`、`unavailable`、`denied`，攜帶已授權來源與受眾；改送文字不能聲稱附件已送。整合現有交付契約，不另建一套傳送系統。

```text
圖片請求
    |
    v
共用頁面／章節／可見性核對
    | 拒絕 ------------------------> 現有安全拒絕
    v
請求來源
    | /coc showpage ---------------> 已授權原圖
    v
Keeper 主動展示
    | 設定=true -------------------> 排入指定受眾圖片
    v
設定=false
    |
    v
已授權的既有描述／原文／地圖脈絡
    | 足夠 ------------------------> 現有敘事／私人文字流程
    | 不足 ------------------------> 已知資訊＋手動看圖提示
    v
現有交付流程保留公開／私訊對象
```

主動交付也須抑制附件，避免其他產生端漏接設定。手動 showpage 經共用授權後走明確獨立路徑；不能在底層 transport 無條件禁圖而連手動請求都擋掉。

## 文字、隱私與權威

- 重用匯入描述或相關原文，交現有 Keeper 流程處理，不新增固定圖片分析／敘事審稿呼叫。
- 不直接把索引前 500 字貼到群組；它是來源脈絡，不是核准公開回覆。
- 保留既有防劇透與章節授權；資料可用不代表玩家已發現。
- 私人文字維持私訊，不透過公開 Narrator observation 或公開回覆洩漏。重用現有私人輸出流程；沒有安全可用描述時，向正確受眾送安全的不足提示。
- 保留已授權 KP 明確揭露的既有語意；一般玩家不能用 showpage 或文字模式取得 KP-only 資料。
- 描述不足時只說已有依據的資訊，必要且已授權時提示 `/coc showpage N`；不猜內容、不偷偷補一次 vision。
- 保留來源引用，區分圖片衍生描述與逐字原文。呈現不能自行建立有劇情或機制影響的事實。

## 儲存與相容性

全站設定不需新增遊戲狀態欄位。無論展示模式，都繼續保存 PDF 圖片、描述與房間圖。舊劇本沒有專用圖說時，使用已授權脈絡或安全的不足提示；不要求重新匯入或背景生成圖說。

## 驗收

透過真實分派／交付界面，使用可控 sender 與模擬 provider：

1. 預設與 true 保留主動公開／私訊附件。
2. false 抑制所有主動附件，涵蓋檢定後續與開場；公開／私人受眾不變。
3. false 下自然語言看圖請求不能送附件，模型旗標不能略過。
4. showpage 在兩模式都能送已授權原圖；一般玩家的未知／不可存取／KP-only 頁面被拒絕，已授權 KP 行為保留。
5. 含秘密的頁面摘要不直接公開；描述不足不捏造、不增加圖片分析呼叫。
6. 圖片匯入、OCR、角色與地圖保存不受設定影響。
7. 文字模式不聲稱已送圖；不新增固定 provider 階段。
8. 全套 pytest、ruff 0.16.8、mypy app、compileall app tests 通過。

## 討論決定

六個行為問題與共同理解皆已確認：全站啟動設定、預設 true、只關閉 Keeper 主動展示、只有 showpage 手動例外、重用描述不新增固定呼叫、維持防劇透與隱私、描述不足用已知資訊與已授權手動看圖提示。共用手動指令授權納入本功能。
