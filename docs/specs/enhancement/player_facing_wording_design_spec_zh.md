# 回合無法完成時玩家讀到什麼、排隊通知持續多久、角色叫什麼名字

[English](player_facing_wording_design_spec.md)

狀態：**已實作**。基準：`main_v2` 的 `f03a110`。

## 問題

兩次真實的五人測試（Haunting 在 `b0e875c`、Dead Boarder 在 `d6f13c3`）顯示，玩家碰到的不只是規則問題：

- Dead Boarder 102 回合中有 15 回合（14.7%）以「這次行動尚未完整處理」結束；其中 9 回合是 `executor_no_action`，幾乎都是玩家走去某處或問某人一件劇本沒寫的事。訊息卻叫玩家「把行動說得更具體」，劇本沒寫的時候這是在怪玩家。這類回合還等得最久（p50 57.5 秒，其他回合 43.0 秒）。
- 排隊通知大約 50 秒（三則）後就停了。同一次測試中五人同時送出最久等了 204 秒，Haunting 最久 255 秒，最後 150–200 秒完全沒有訊號。
- 系統訊息用登記的英文名稱呼預設角色（「The Tough Guy 的背包已確認…」，102 回合出現 15 次），旁白卻叫同一個角色「硬漢」。

## 限制：只改措辭與節奏

回合的判定、工具、鎖與時間都不變。會 fallback 的回合仍然因為同樣的原因 fallback，只有玩家讀到的那句話不同。存檔、已存的遊玩紀錄、回合日誌、送出文字的文字日誌與 id 永遠不會看到別名：別名是在它們保存之後才寫的。唯一保存帶別名文字的地方是已送出訊息的更正回條（`narrative_message_receipts`），因為玩家更正時引用的是自己讀到的字。文字在套用別名之後才切成 Discord 訊息，因為別名會改變長度。

## 變更

- **`executor_no_action`** 現在說：劇本裡沒有足夠的內容可以據以裁決這個行動，守密人沒有替它編造；可以改問劇本中已經出現的人物、物件或地點，如果行動很籠統，也可以補上對象與方式再試一次。因為原因代碼分不出這兩種情況，所以兩種都寫。對於要玩家改試別的做法的原因（`executor_no_action`、`unsupported_action`、`no_scenario_evidence`），再加一行說明桌上已經看到什麼：「目前已在劇情中出現、可以接著問或查看的有——…」：來自劇本索引的地點與人物，只列名稱或別名已經出現在**公開旁白**中的，並且**照旁白用的寫法**列出（只被旁白用別名提過的項目，絕不會以正式名稱印出，因為正式名稱可能就是秘密）；最近出現的在前，各最多五項；玩家自己打的字與非公開旁白不算。只出現在劇本也列出的較長名稱之中的名稱（「房東太太」這個項目裡的「房東」）不算，ASCII 名稱不得緊貼其他 ASCII 字母或數字；沒有任何索引列出的較長詞語無法分辨，所以短名稱仍可能在其中被比對到，再加最多三條公開線索（截到 24 字）。所以它只會重複玩家已經知道的事，不會點名沒去過的地點或尚未揭露的人物。不呼叫模型、不改狀態，還沒有任何東西出現過時就不加這一行。
- **排隊通知**維持 10 秒的第一則，之後的間隔逐漸拉長（20、30、45，最後 60 秒），最多七則：10、30、60、105、165、225、285 秒。一般不到一分鐘的等待仍然最多看到三則。每則都重新讀取位置，所以是倒數。
- **`CHARACTER_DISPLAY_ALIASES`**（JSON 物件，預設空）：在文字送往 Discord 的地方套用，而不是在回覆管線裡：`delivery.shown` 對每一則公開回覆、互動回覆與訊息、直接訊息、被編輯的訊息與私人訊息執行 `presentation.character_aliases`（`reply`、`send_direct_message`、`send_interaction_message`、`edit_interaction_message`、`send_dm`，以及 Help 選單的確認提示），所以 `/coc characters` 這類直接指令回覆也涵蓋。它一次掃描就把每個登記名寫成它的別名（先比對較長的，所以替換結果不會再被搜尋；字面插入）。ASCII 名稱不會比對到其他 ASCII 字母或數字之內。中文沒有詞界，所以登記名若是某個沒人設定的較長名稱的一部分（「馬可波羅」裡的「馬可」）也會被換掉；把較長的名稱也列進去、對應到它自己，就能保留它。預設不變。不是「文字對文字的 JSON 物件」的值會被忽略並像其他錯誤設定一樣在啟動時回報。設定寫在 `docs/guides/configuration_profiles.md` 與 `.env.example`，同時補上先前新增卻沒有列出的 `LOCK_HELD_WARNING_SECONDS`。

## 沒做的

- 分辨「劇本沒寫」與「行動太籠統」需要 Executor 說明是哪一種；在那之前，那句話涵蓋兩者。
- 旁白把索引名稱翻成不同說法時（索引是英文、旁白叫別的名字）不會比對到，所以那一行會比較短，但不會出錯。劇本沒有索引的物件不會列出，除非它是公開線索。
- 「有限即興」（讓守密人編造無害的場景陳設）評估過，決定不做：維持有依據的原則，改為引導玩家。
- 沒有告訴 Narrator 這個別名，所以 Narrator 用的名字若與設定的別名不同，仍然是兩個名字。設定的別名應該和 Narrator 已經在說的一致。
