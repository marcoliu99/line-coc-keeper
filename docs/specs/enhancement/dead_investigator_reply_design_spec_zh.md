# 已死亡調查員的發言，回覆「已死亡」

[English](dead_investigator_reply_design_spec.md)

狀態：**已實作**。基準：`main_v2` 的 `112a22a`。來自 2026-10-12 的 Haunting rerun3（Caleb Ward，第 50 到 98 輪）。

## 問題

戰鬥中一擊十二點傷害，殺死了只有十點 HP 的調查員；桌上也被告知「十二點傷勢足以奪去他的性命」。戰鬥引擎在他的傷勢紀錄裡同時留下 `dead` 和 `unconscious`，狀態標籤是 昏迷 和 倒地。戰鬥結束後，他的玩家接下來五十次發言都沒有被當成死者的發言回答。`unconscious_wake` 不處理死亡的調查員（「死亡不歸這條規則」），所以這些發言都交給執行器；執行器讀到「HP 0、昏迷、倒地」，要嘛判成做不到（固定的「這次行動目前無法繼續」），要嘛讓敘事者一直寫「Caleb 仍昏迷倒地」。沒有人告訴他已經死亡，也沒說玩家接下來能做什麼。

## 變更

戰鬥之外，傷勢紀錄寫著 `dead` 的調查員，其玩家的發言直接由狀態回答，不經過任何模型（`unconscious_wake.dead`、`dead_reply`，`supervisor._prepare` 的第一個檢查）：「{name} 已經死亡，不能再行動了。想繼續參與的話，請告訴守密人，由他安排新的調查員；其他調查員可以繼續。」同一個判斷也讓這句話不做劇本檢索預取、不在場景地圖上移動該調查員。戰鬥進行中仍由戰鬥引擎決定。瀕死（`dying`）不算死亡，仍然等待急救。

## 沒有改的

引擎仍會在死亡的調查員身上留著 `unconscious` 和 昏迷 標籤。這個不一致先不動：回覆已經不再依賴它。

## 驗證

`tests/test_unconscious_wake.py`：死亡調查員的發言不經過執行器就得到死亡回覆，而且沒有「昏迷」；只有傷勢寫著 `dead` 才算，瀕死不算。
