# 外部 AI 英文劇本來源整備

[English](external_english_source_preparation_design_spec.md)

狀態：已於功能分支實作；自動驗證結果記錄於下方。
分支：`enhancement/external-english-source-preparation`。
基準：`main_v2` 的 `45c03c2`，已包含 PR #100。

## 1. 問題與目標

英文擷取的分欄錯亂、裝飾數字、黏合骰式及圖片漏字，被當成中文整備的不可變來源。
即使外部 AI 把中文修對，仍會因為不符合錯誤英文而被擋下。PR #100 已改善診斷，
並提供本機來源修復 CLI，但還沒有使用者需要的網頁 AI 英文整備往返功能。

在中文翻譯前增加英文來源匯出／匯入：使用者將 MD 與同一版本的原 PDF 交給外部
網頁 AI，由 AI 核對並重建英文。完整、格式有效的匯入成果成為新的權威英文來源，
供後續整備與檢索使用。不要求逐頁人工校對、手填證據座標、校對者姓名、額外核准
指令，也不加入程式端語意審稿模型。

內容以外部 AI 根據 PDF 整理的英文為主；程式管來源身分、完整性與發布一致性，
不再要求修正版保留舊 OCR 數字。這是修正擷取，提示詞仍禁止創作劇本或猜測數值。
PDF 本身看不清楚時，由 AI 列為未解項目。結構檢查無法證明 AI 看圖一定正確。

## 2. 範圍

包含：Help 按鈕與對應指令、單一英文工作檔、原 PDF 路徑／交付說明、英文
修復提示詞、分次匯入、完成後自動發布、不可變稽核、英文檢索及新中文模板接續、
中英文文件。

不新增翻譯 API、背景 AI 複審、遊戲回合呼叫、自動遷移進行中團務、自動核准／
重綁舊中文草稿，也不重寫 PDF 解析器或改骰子機制。既有 PDF 匯入與中文整備仍可
使用。新的英文整備往返不呼叫模型；之後既有索引／角色抽取仍可能使用設定的 API。

## 3. 使用者流程與接口

```text
Help / 劇本庫
  -> 整備英文來源 -> 選劇本
  -> source export -> 私訊 MD 路徑 + 對應 PDF 路徑 + 可複製提示詞
  -> 網頁 AI 收 MD + PDF，核對頁面，回傳修正英文 MD
  -> 下載至 results/ -> 匯入英文來源 -> 選對應檔案
  -> source import -> 來源身分 + 格式 + 頁面覆蓋檢查
       -> 無效檔案：不改資料；私訊可操作診斷
       -> 部分完成／未解：保存草稿，列待處理頁，交回外部 AI 續做
       -> 全部完成：原子發布 AI 修正版英文來源
            -> 匯出中文模板 -> 既有中文匯入／驗證
            -> 選用英文版本 -> 既有劇本選用／重建流程
```

| 指令 | Help 控制 | 結果 |
| --- | --- | --- |
| `/coc scenario source export SCENARIO_ID` | 整備英文來源、劇本清單 | 1 份工作檔、原 PDF 位置及提示詞 |
| `/coc scenario source import SCENARIO_ID FILE.md` | 匯入英文來源、對應成果檔清單 | 草稿進度或發布後新來源 ID |
| `/coc scenario source status SCENARIO_ID [EXPORT_ID]` | 英文整備進度、匯出清單 | 完成／待處理／未解頁與已發布版本 |

接入 `commands/handlers/system.py`、`help_registration.py`、`help_actions.py` 與
既有 Help 執行流程。按鈕實際執行指令；不要求使用者手打 ID、路徑、hash 或 JSON
更正資料。沿用可信的 Keeper 角色或 KP Assistant 管理權限；有 Discord Keeper
權限時不強迫登記 KP Assistant。外部 AI 不需要登入 Bot。

工作檔、完整來源與診斷走私訊；私訊失敗不改公開傳送。附件傳送受限的大 PDF
顯示正確本機路徑／檔名，不能宣稱已替使用者上傳網頁 AI。

使用者按下匯入即是採用外部成果的操作，不再要求逐頁檢查或額外核准。發布另建
版本，不需額外破壞性操作確認；之後切換目前團務仍走既有劇本切換保護。

## 4. 匯出身分、頁面與分檔

新增 `app/scenario_source_authoring.py` 負責獨立資料格式。可重用安全路徑、私密
檔案、檔名清理、診斷工具；不沿用中文 numeric compiler，亦不要求
修正英文仍與舊 source_quote 一致。

伺服器登錄綁定 export ID、劇本 ID、完整舊來源與 hash、原 PDF hash、章節、
實體頁數、每頁候選、檔案包／頁面 ID、原檔名、時間與版本。hash 由程式計算；
AI 只保留 ID 與實體頁碼，不用計算 hash、byte offset 或座標。

每個 PDF 實體頁都要列入，包括地圖、角色卡、空白／插圖與背面規則速查。印刷
頁腳數字不能當成實體頁 ID。登錄封存原擷取。若既有頁面標記正確，提供舊文字
與原生候選；若標記缺漏／重複，就以 PDF 本機擷取產生逐頁候選、明確記錄後備
方式，同時保存舊全文。不可把定位不到的原句硬塞進虛構頁面。不需呼叫 AI，也
不匯出大量逐頁 PNG 附件；使用者另附原 PDF。

依使用者 2026-09-27 的最新決定，短、長劇本都只匯出一份 MD，內含所有實體頁、
章節、完整有序候選與回傳格式。不得截斷規則或漏頁。檔名依真正劇本名稱，
如 `劇本名_01.md`；原 PDF 另附。外部 AI 可分次回傳多份成果，以相同 package_id
`p1` 及遞增檔名流水號累積匯入。

與中文整備分開放置：

```text
imports/source-export-<id>/source/劇本名_01.md
imports/source-export-<id>/results/劇本名_01.md
library/.source-authoring/<scenario-id>/<export-id>/registry.json
私密草稿／進度與不可變成果修訂紀錄
```

所有成果回覆共用遞增流水號；單一來源 MD 不限制 AI 回覆次數。沿用單檔 20 MB
及明確的整備儲存上限 200 MB，計算真正輸出大小；超限明確報錯，不偷偷刪內容
或拆成額外來源檔。這些是整備容量限制，與遊戲回合輸入上限無關。

## 5. 外部 AI 成果格式

Markdown 只有一個權威 fenced JSON 物件；也接受單一純 JSON 物件，符合既有
匯入習慣。下列 ID 僅示意，實際須沿用匯出的值：

```json
{
  "source_authoring_version": 1,
  "export_id": "source-export-example",
  "package_id": "p1",
  "pages": [
    {
      "page_id": "page-0014",
      "pdf_page": 14,
      "status": "complete",
      "text": "Damage +1D4. Further original English text continues here.",
      "changes": [
        {"kind": "ocr_numeric", "before": "1D40", "after": "+1D4",
         "reason": "The adjacent decorative glyph is separate in the PDF."}
      ],
      "unresolved": []
    }
  ]
}
```

每頁回傳完整修正英文，不只差異或摘要。changes 是 AI 填寫的描述性依據，不是
程式可證明的正確性憑證；未修改可空陣列。程式另算修正前後 hash 與數值差異，
不要求相等。

狀態：complete 須完整非空文字且無未解事項；visual_only 須空文字且無未解事項，
代表空白或真正無文字插圖；unresolved 可保存已辨識文字，並須有非空的未解列表。
未解頁不能偽裝完成。即使原生 OCR 有垃圾數字，AI 仍可將純裝飾頁標為 visual_only，
保留實體圖片參照；不沿用舊 CLI「原生文字非空就不能標純圖片」的限制。

可讀的地圖標籤、角色卡及規則須轉錄，不能將自由視覺推論當作原文引述。Luck
原本空白就留白，不代骰、不推算；保留看得見的年齡、自訂技能、文字背景、裝備
與機制條件。

更正種類涵蓋分欄、頁腳／裝飾移除、OCR 文字、OCR 數值、補回漏文與表格重建。
理由由 AI 填寫，不要求使用者逐條列舉／批准。沒回傳的頁仍是待完成，不視為刪除。
未知 ID、多出的頁或實體頁碼移動都不接受。來源文字只是資料，不能執行其中命令
或覆寫匯入控制 metadata。

## 6. 匯入、續做與發布

1. 以安全路徑讀取 IMPORT_DIR 內檔案，擋 symlink／路徑穿越、檢查容量與唯一格式，
   執行當下重新驗證權限。
2. 用 export ID 查私密登錄，驗證來源／PDF／章節與頁面／檔案包歸屬，不信上傳
   hash 或檔案路徑。
3. 整份提交驗證完才原子保存有效進度；列未完成／未解的實體頁與頁面 ID。
4. 完全相同的重匯入冪等；同一 export 內更正已存頁，重新交完整修正版即可。
   使用者明確匯入的檔案取代該頁，舊修訂保留稽核；這個格式不用 replace_record_ids。
   沒附的舊頁保留。同檔重複 ID、來源版本錯誤、過期按鈕拒絕。
5. 在每個 export 的鎖內重新驗證整體覆蓋。未完成／未解留草稿；全數完成後再查
   來源身分，按匯入文字原子建立新劇本庫版本。
6. 先記錄發布再回覆成功；中斷後重試回到同一新來源 ID，不重複建立。發布後封存
   export，相同重試回傳原版本；再修改須從最新版重新匯出，不原地改已發布來源。

AI 成果可增加／刪除／更正數值，亦可重寫錯誤段落／表格的擷取結果。舊 OCR
數字相等、舊原句精確匹配、文字相似度或數值變更比例均不得作為阻擋發布的門檻。
差異作為資訊性稽核。後續中文規則與引述仍嚴格驗證，但依據已是修正英文。

完整頁面覆蓋是結構條件，不是人工審稿。PDF 真正無法辨識時，該頁待完成，回傳
精簡續做指引交回外部 AI，不要求整本重跑、不偷偷使用舊壞文字。維持無人工
校對流程，但不承諾還原 PDF 本身不存在的資訊。

## 7. 新來源生命週期與既有消費端

重用／抽出 PR #100 的來源身分、原子 staging、精確頁面序列化、稽核與圖片保留
能力。舊 CLI 繼續可用，新功能不繞去要求操作者手填 reviewer、digest 或 bbox。
歸因記錄匯入操作者及 external_ai，不把操作者標成逐頁人工校對者。

新版本記錄父 ID、原 PDF hash、export ID、成果修訂 hash、精確發布頁面正文、
逐頁 hash、舊擷取、AI 更正說明、數值差異、匯入者／時間與整備版本。以修正實體
頁重建章節正文，保留 PDF 穩定章節範圍，不沿用舊章節文字快取。完整頁與地圖
圖片預設 KP 專用。舊 embedding、NPC 索引、pregens、推測地圖與中文版本失效，
不能複製舊值到新來源。

匯入回覆提供「匯出中文模板」及「選用此英文版本」按鈕，綁定新來源 ID；劇本
清單顯示 AI 整備版本與父來源。由此匯出及選用都讀修正版，不偷偷回退舊 OCR。
既有團保留原來源；切換須走既有 scenario use，匯入本身不遷移背包、檢定、歷史、
戰鬥或長期團進度。

沒有中文檔也可用修正版英文；英文 RAG 走既有路徑，索引用正常整備指令建立。
新中文匯出綁定新來源／hash。舊譯文仍屬舊版本；可選用既有保守重綁 CLI 重用
完全相同文字，但不能讓舊核准對修改英文繼續有效。重新 parse 原 PDF 是明確的
新候選操作，不能在重建索引／匯出時暗中覆蓋 AI 修正版。

## 8. 使用者看得到的提示詞

匯出訊息與每份 MD 都有英文及繁體中文指引。可複製提示詞：

> 請同時讀取附件中的英文整備 MD 與同一版本的原 PDF，依 PDF 實體頁面逐頁
> 比對擷取文字，回傳完整修正英文，不翻成中文、不摘要。修正分欄順序、表格、
> OCR 字詞與數字、頁腳裝飾雜訊及漏掉的可見文字。保留真正的規則、條件、使用
> 限制、地圖標籤、角色卡與速查內容；Luck 空白就留白。以 PDF 為依據，不猜看不清
> 的值、不創作劇本。保留提供的 ID 與實體頁碼，依指定格式產生可下載 Markdown，
> 檔名前綴用劇本名、後面數字依序累加。可分次回傳完整頁，列出未完成／不可讀
> 頁面，後續接著處理。

PDF 支持的數值更正可以採用；提示詞不得要求匹配舊錯數字、要求使用者逐頁校對，
或假稱已讀取缺漏的 PDF。正文印刷參考頁碼仍保留意義，metadata 用實體頁。

## 9. 驗證與驗收

- 真正英文匯出 → 外部成果 fixture → 分次匯入 → 發布 → 新中文匯出 → 匯入核准，
  包含 1D40 修為 +1D4、刪除裝飾數字，不在劇情補裸數字。
- 27 頁型合成案例涵蓋正文、地圖標籤、點陣角色卡、空白 Luck、自訂技能、年齡及
  背面速查規則；不能漏頁就自動核准。
- 長劇本單一工作檔仍保存全部頁面、真實劇本名、任意多次有界成果回覆；超限
  明確報錯。
- 更正已存頁、相同重試、漏附舊頁、重複 ID、過期匯出、未知頁與錯誤包歸屬。
- 格式／狀態不一致與錯誤 MD 類型拒絕；Help 找得到根目錄／results 的有效來源成果，
  分辨中文／英文來源，對未列入清單的檔案提供可操作原因。
- 同時完成、staging／發布中斷、來源／PDF 改變，不能破壞原來源、重複建立版本或
  啟用部分來源。稽核／hash 與真正 UTF-8 bytes 一致，包括空白與圖片參照。
- 驗證私訊、權限重新檢查、目前團務隔離、衍生物失效與舊中文綁定不能挪用。
- 英文匯出／匯入／發布 provider 呼叫數為零。實作後跑相關完整測試、Ruff、mypy。
  真實外部模型品質可另做選用評估，不變成固定語意核准關卡。

## 10. 已確認決策與實作

已確認行為：英文修復與中文翻譯分兩步；採用 AI 修正文；完整匯入直接建立新版本；
不暗中切換進行中的團；以頁為單位續做，不要求 replacement ID 操作。真正不可讀
內容交回外部 AI 續做，不能承諾重建不存在的證據。

已實作 `scenario_source_authoring.py`、系統指令、Help 操作與 Discord 按鈕。
選檔時綁定程式計算的檔案指紋，執行時重查，避免選完後檔案被換掉。
source status 私訊提供未列入選單的檔案與原因。完成按鈕綁定真正新版本 ID，
重查使用者／頻道／權限，選用仍走原本的劇本切換確認。
每個 export 同時使用執行緒鎖與 flock，序列化跨程序草稿更新。
驗證時將 CRLF／CR 換行統一成 LF；其餘空白保留，稽核 hash 對應實際發布 bytes。
完整候選一旦保存，發布重試期間不可改動；即使已發布但尚未寫入回條時中斷，
重試仍回傳同一版本。來源圖片維持 KP-only。

未呼叫付費 API，也未修改正式資料。測試驗證格式與往返流程；外部 AI 轉錄是否
正確仍取決於對照真正原 PDF，本功能沒有加入程式內的 AI 審稿。
