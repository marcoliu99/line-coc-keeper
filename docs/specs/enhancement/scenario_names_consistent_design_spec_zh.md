# 劇本的人物與地點固定用同一個中文名

[English](scenario_names_consistent_design_spec.md)

狀態：**已實作**。基準：`main_v2` 的 `7dc932c`。

## 問題

劇本索引（`/coc index`）已經把每個 NPC／怪物和主要地點翻成繁體中文，英文原名列在別名裡。Keeper 和 Narrator 都看得到索引，但沒有任何規則要他們照索引的名字寫。所以同一個名字可能這回合寫英文原名，下回合又換一個新譯名。

讓長篇 LLM 翻譯保持一致的工具通常做兩件事：給模型一份固定的譯名表，並在產出後把名字改回來。原因是提示裡的譯名表大多數時候會被遵守，但不是每次都會。

## 改動

- **提示規則。** 有索引時，靜態提示多一段「譯名」：提到上面列出的人物或地點，一律照「・」後面那個中文名寫，每次都一樣；別名和英文原名只用來認出是誰，不寫進敘事，也不另取譯名。身分還沒揭露的人物，照樣用玩家目前知道的稱呼。列出的名字還是英文（例如地圖上的地點）時，第一次提到就取一個中文譯名，之後沿用。
- **送出的內容固定名字。** 回覆流程新增只改顯示的 `scenario_names` 步驟，在 `finalize` 之後、`player_text` 之前執行，套用到整則回覆、私訊和私人按鈕，所以送出流程附加的結果行和線索行，跟敘事用同樣的名字。它呼叫 `presentation.use_scenario_names`，把索引列出的英文別名改寫成該條目的中文名，例如「Corbitt」→「柯比特」、「Corbitt's」→「柯比特的」。
  - 不分大小寫，只比對完整單字，所以「Corbittson」不會被改。
  - 只用三個字母以上、而且只對應一個條目的別名。兩個條目共用的別名（例如「Deep One」同時是深潛者和深潛者（幼體））不動。
  - 調查員和預設角色的名字永遠不改；別名如果是其中某個名字的一個字（「Malcolm Carter」裡的「Carter」）也不改。
  - 索引沒列的英文字一律不猜。
  - 中文名要已經告訴過玩家（這則回覆或先前的公開敘事出現過）才會改寫：索引的中文名可能是偽裝背後的真實身分（「Masked Man」其實是兇手約翰），改寫絕不能變成爆雷的來源。
    - 這則回覆才揭露的名字，只改寫揭露之後的部分，所以「Masked Man 靠近。你認出他是約翰。」的第一句維持原樣。
    - 出現在較長的索引名或調查員名字裡（約翰遜裡的約翰）不算揭露；只有一個字的名字（國王裡的王）也永遠不算。
    - 中文名和調查員或另一個條目相同的條目，一律不改寫。
  - 是遊戲用語或技能名的別名（「DEX」、「Dodge」），以及調查員的顯示名稱（`CHARACTER_DISPLAY_ALIASES`），一律不改寫。
  - 名字前後（略過空白和英文標點）緊接著英文字時，那是敘事引用的英文（「Will he return?」、「May, I enter?」），不是人名，保持原樣。
  - 私訊和公開敘事用同樣的名字。私訊也可以用該讀者自己被告知的名字，但只限依送出順序、到那一則為止已告知的。
  - 和 `player_text` 一樣只改名字的寫法，送出流程驗證過的事實不變。改寫後的公開回覆仍要通過送出流程的劇透與事實衝突檢查（`turn_delivery.rewrite_still_safe`），沒通過就顯示已驗證過的英文寫法。
- **對現有遊戲。** 其他都不變：戰鬥、檢定、存檔和索引本身都不動。已經建好索引的遊戲，下一回合起兩項改動就生效。

## 驗證

`tests/test_scenario_names.py`：

- 英文原名和所有格會改成索引的中文名。
- 較長的單字、兩個字母的別名、兩個條目共用的別名都不動。
- 調查員的名字保持原樣，英文引文裡的名字也是。
- 私訊用同樣的名字。
- 只有在有索引時，提示才帶這條規則。
- `scenario_names` 只改顯示，在 `finalize` 和 `player_text` 之間執行，涵蓋附加的結果行和私人按鈕。

`tests/test_reply_pipeline.py` 的流程順序加入了新步驟。
