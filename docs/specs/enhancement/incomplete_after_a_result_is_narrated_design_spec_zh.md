# 已有結果的未完成回合，用故事說明

[English](incomplete_after_a_result_is_narrated_design_spec.md)

狀態：**已實作**。基準：`main_v2` 的 `8d7a55a`。來自 2026-10-13 的 Scritch-Scratch 200 輪（第 21 輪；前一次測試的第 67 輪也有同樣情形）。

## 問題

隊伍走上小屋後方的公共步道。執行器擲了偵查（極難成功），替看到吊掛鼠屍的四位調查員各擲了理智檢定，然後把回合交回 incomplete：劇本要求偵查搭配聆聽，它沒有擲聆聽。未完成的回合會略過敘事者，玩家於是只讀到四行擲骰結果，加上「這次行動尚未完整處理…剛才的結果已經記錄，但這次行動的後續守密人還沒處理完；請接著說明你想怎麼做」，完全沒讀到調查員看見了什麼。

## 變更

`prompt_config.narrates_what_was_done(result, state)` 在下列情況為真：這是執行器自己放棄的未完成回合（`model_incomplete`、備援原因 `executor_no_action`），所有工具都成功，而且擲過骰或改了狀態（`dice_rolled`、`resolved` 或 `state_changed`），沒有任何東西在等人（結果裡和遊戲狀態裡都沒有待處理的檢定或 Luck 決定），沒有戰鬥進行或在這回合開啟，也沒有被擋下的劇本依據。這種回合會讓敘事者執行（`narration_replaced` 為假），一致性步驟直接回傳敘事文字，擲骰結果行照常附在其後。敘事者的事實區塊說明列出的結果已經發生，要說它們顯示了什麼，並把下一步交還給玩家；沒擲的檢定、沒做的事不可寫成已完成，也不可說系統出錯。如果敘事本身失敗，失敗訊息會被丟掉（與說明型的拒絕相同），改用固定的提示回覆。

這種回合不進義務檢查（與說明型的拒絕相同）：義務檢查若在故事之後開出新的檢定，這回合就又不符合條件，故事會被提示取代；而且這回合的機制執行器已經處理過了。

不變的部分：有工具失敗、有等待中的項目、有戰鬥、或什麼都沒做的回合，仍然使用原本的提示。

## 驗證

`tests/test_turn_fallback.py`：判斷在「乾淨、擲了骰的未完成回合」為真，在每一種排除情形為假（什麼都沒做、有工具失敗、有待處理檢定、戰鬥開啟或進行中、其他備援原因、遊戲狀態裡有等待中的檢定）；回覆是敘事文字而不是提示、事實區塊帶有指示、敘事失敗時仍有提示；端到端的回覆就是敘事者的文字。
