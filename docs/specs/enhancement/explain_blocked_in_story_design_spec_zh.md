# 劇本做不到的行動，用故事說明

[English](explain_blocked_in_story_design_spec.md)

狀態：**已實作**。基準：`main_v2` 的 `c46e341`。來自 2026-10-12 Scritch-Scratch rerun3（第 57、69、81、93 輪）。由維護者要求。

## 問題

測試腳本每隔十二輪就要隊伍「到 Muscoby 圖書館查資料」。村裡沒有圖書館。前四次守密人用故事說了沒有，並指出最近的一間（二十英里外的 Appleford）。從第五次起，執行器查過劇本後把回合判成 `blocked`，玩家只看到「這次行動目前無法繼續。依目前的劇本與場景狀態，這個行動無法進行；請改試別的做法。」，沒說為什麼，也沒說可以去哪。

## 變更

`prompt_config.explains_in_story(result, state)` 在下列情況為真：回合是 `blocked`、原因是 `unsupported_action`、這回合的劇本搜尋回來的是真正的段落（`turn_fallback.found_scenario_text`：有頁碼標頭，而不是只有「（沒有找到相關內容）」——那是成功的呼叫、結果卻非空），而且什麼都沒改——沒有待處理檢定或 Luck 決定、沒有狀態變化、沒有擲骰、沒有結算檢定、沒有開戰、沒有劇本依據不足的封鎖、沒有自己的公開拒絕文字，也沒有進行中的戰鬥。這樣的回合：

- 由敘事者來寫（`narration_replaced` 為 false），不再略過它直接寫固定文字；
- 敘事者的事實區塊多一段【這個行動在劇本裡無法進行】：用故事說明為什麼，只指出劇本裡有的地點和人物，不補造，也不寫成行動已完成；
- `enforce_mechanic_check_consistency` 保留敘事者的文字。敘事者沒寫出內容時，仍退回固定文字。

其他 blocked 或 incomplete 的回合不變，進行中的戰鬥仍用「輪到誰」的說明。

## 風險

敘事者要遵守這段指示；守衛和義務閘門照常檢查它的文字。`unsupported_action` 原本就有的一次重試不變。

## 驗證

`tests/test_turn_fallback.py`：這樣的回合由敘事者的文字回答，事實區塊有說明；敘事者沒寫出內容時退回固定文字；任何有做過事的徵象（擲骰、結算、狀態、開戰、待處理檢定或 Luck 決定、依據封鎖）、其他原因、`incomplete` 回合或進行中的戰鬥，都維持固定文字。
