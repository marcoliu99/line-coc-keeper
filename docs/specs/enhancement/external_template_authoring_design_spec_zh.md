# 外部 AI 中文模板整備與匯入診斷

[English](external_template_authoring_design_spec.md)

## 狀態與範圍

分類：`enhancement`。狀態：**已實作；網頁 AI 易用性與真實 API 效能試跑尚未執行**。基準：`main_v2` 的 `c05e152`（2026-09-27）。此提案延伸 PR #83，保留原文依據、章節隔離及核准後才能啟用的要求，並納入長期團的完整資料保存與按需取用。

PR #94 實作整備 v1、執行期 v4 與舊 v3 相容匯入；後續三檔方案將新匯出改為 v2，保留 v1。以下設計決策的實際行為與限制見第 10 節。

## 1. 已觀察失敗與原因

回報的《鬼屋》匯出只有一個來源單元 `chapter-01-u1`，涵蓋 PDF 位置 1–27，共 71,612 個 Unicode 字元。匯出 hash 與目前劇本一致。Gemini 回傳四筆記錄，沿用同一來源 ID，卻改寫頁碼（包含 28–40 頁），並刪除 `source_spans` 與 `type`。另有不支援的可見範圍 `all`、規則欄位使用一般字串，以及 KP 專用記錄帶公開內容等問題。

唯讀驗證重現頁碼／章節錯誤；僅在記憶體中修正頁碼後，下一個錯誤為缺少 `source_spans`。原檔與正式狀態均未修改。提供的 profiler 未捕捉匯入驗證器，不能據此量測匯入耗時。

`_blocks()` 辨識 Markdown 一、二級標題。這份解析來源缺少可用的該層級標題，整章因而成為一個單元。簡短匯出說明接著要求外部模型同時切分語意、計算位置、保留來源，並從空陣列推測格式。匯入器只回報第一個籠統錯誤。拒絕不合法內容是必要的，但整備契約與診斷需要改善。

## 2. 目標與非目標

1. 使用者將匯出的 MD 上傳網頁 AI、貼上內附指令、下載完成的 MD，再使用現有 Help 匯入按鈕。
2. 程式負責 hash、頁碼／章節映射、來源位置與覆蓋率計算；外部 AI 負責忠實中文翻譯與明確的規則／原文引述。
3. 儲存匯入候選前提供可操作的驗證報告；預覽、核准與啟用維持分離。
4. 遊戲中重用預備內容，不固定新增 LLM 往返，也不新增翻譯 API 依賴。

不包含：自動背景翻譯、瀏覽器自動操作、把摘要視為完整覆蓋、猜測缺漏規則、默默修正不明確的來源比對，或在本次文件工作中翻譯正式劇本。改善匯出包裝不能修復錯誤的 PDF 閱讀順序；損壞段落須保留疑點，指向 PDF 校閱／重新解析。

## 3. 匯出包與來源單元

提議的匯出內容包含：可複製的網頁 AI 提示詞、不可變來源片段與單元 ID、可編輯翻譯記錄、一筆完整合成範例、欄位限制與完成檢查表。範例放在匯入 JSON 之外，避免誤匯入。

在劇本庫保存不可變匯出清單，包含 `export_id`、來源／章節 hash、整備格式版本與切分版本。精確文字位置與單元 hash 由伺服器保存；匯入 MD 不能重新定義映射。重新解析或改變切分方式須建立新匯出識別；缺少或過期的識別要求重新匯出。

有可靠場景／標題資料時沿用；缺少標題時，使用保留精確原始位置的確定性頁面／段落單元，並標記不透明或損壞段落。這些是來源定位依據，不表示規則在頁尾結束。另附帶 ID 的鄰近來源上下文；條件／後果跨單元時須明確建立關聯。只作上下文的內容不算已翻譯覆蓋。

編譯父層保留既有 `_blocks()` 來源 ID；新的較小單元 ID 映射到父層文字範圍，不改變舊 v3 解讀方式。整備記錄跨越父層時，編譯器可輸出多筆互相關聯的新版記錄。不能只為符合大小限制而切斷規則；未處理的跨單元規則阻擋核准。

初始可設定的包裝目標為每批最多 8,000 個原文字元；完整單元可超過目標，但須明確警告。這是待驗證的易用性目標，不是量測後的最佳值，也不是遊戲投影上限。每批有識別、預期單元清單及進度，允許分批回傳而不遺失未完成工作。現行 v3 的 6,000／12,000／18,000 字元限制是舊投影器行為，不再作為新版整備或資料保存的驗收上限；新版每次取用預算見第 4A 節。

## 4. 整備格式與編譯

新增獨立的 `authoring_version: 1` 封套，不把它偽裝為現行 `schema_version: 3`。此修訂提議編譯目標為 runtime schema v4，並提高 compiler version，明確區分新依賴與投影語意。封套必填 `export_id`、`batch_id`、`records`。整備記錄包含唯一 `id`、`unit_ids`、`type`、`name`、`aliases`、`keywords`、`visibility`、`public_text`、`kp_text`、`rules`、`related_record_ids`、`uncertainty`。可編輯資料不含執行期來源欄位，改由匯出清單重建。

規則保留目前五種欄位：trigger/check/success/failure/exceptions。每個已填欄位包含 `text`，以及帶有 `unit_id` 與精確 `source_quote` 的 `evidence`。編譯時要求引述在指定單元中精確且唯一；多處相符須釐清或重新切分。不能模糊比對或虛構位置。需要多筆引述時，編譯成多筆完整規則，或回報無法表示；不能擴大引述納入無關文字來通過驗證。

每個分配的來源單元都須完整翻譯，或保留會阻擋核准的未解決狀態。單元覆蓋只是結構覆蓋，不證明翻譯忠實。數值／否定檢查、規則引述、私人預覽與校閱仍然必要。所有疑點持續保留，直到明確解決。

編譯器由登錄資料產生可信任的頁碼／章節／位置欄位，重建原文片段、映射依賴，保留 v3 的來源、權限、引述及覆蓋驗證，並由 v4 改採完整儲存與有界投影。內容超過舊投影上限本身不構成匯入或核准錯誤；明確的檔案／儲存資源限制仍須驗證。可推導明確的來源資料，但不能修補無依據的宣稱、翻譯缺漏內容或默默改變隱私。KP 專用記錄帶公開文字應報錯，不自動決定公開。

部分批次草稿與可遊玩版本分開儲存。完整且驗證通過的合併內容，才透過原子儲存成為待校閱候選。相同批次重送須具冪等性；ID 衝突或改寫已提交內容須明確取代並重新驗證。部分匯入不得改變啟用版本。

## 4A. 長期團：完整保存與每次取用預算

1. **三種大小分開管理。** 劇本庫保存完整已校閱資料；整備批次只控制外部翻譯工作量；遊戲投影預算只控制本次送進模型的內容。不得因單筆超過 6,000 字元、關聯超過 12,000 字元而要求刪除情節、改寫規則或拒收整份長劇本。
2. **完整記錄與可檢索片段分離。** 保存完整記錄及規則群組；索引片段有穩定 ID、父記錄與精確來源範圍。背景描述可按段取用；護甲、攻擊、觸發、費用、每輪／每戰限制與例外屬裁決相關的必要依據。不能把截短摘要當成完整規則。
3. **有型別的依賴，不預先展開整張關聯圖。** v4 區分 required_for_adjudication、conditional、background 關聯，保留適用行動／條件與原文依據。外部 AI 可提議分類，校閱前不得自行降低機制依賴的重要性。未知條件按可能必要處理。搜尋先選目標場景／NPC，再合併適用的必要依據；去重並偵測循環。本地查詢本身也有節點／工作量上限，達上限必須標示未完成。
4. **依模型與本回合剩餘容量計算預算。** 以 token 估算輸入容量，扣除系統提示、工具、最新狀態、保留歷史、輸出預留與安全餘量；取應用設定與可用容量的較小值。未知 tokenizer 採保守估算並標示；字元數只作資源防護，不能假裝等於 token。沿用共用 token 准入，不繞過速率／等待限制。預算不足先省略可選背景，不省略必要規則。
5. **回傳可驗證的完整性資訊。** 結果包含 record_ids、included_fragment_ids、missing_required_ids、deferred_optional_ids、blocked_dependency_count、complete_for_action、continuation_token，以及明確原因。完整性是相對於宣告的行動與已知依賴；中文有命中或機器欄位 complete 不證明未知語意缺口不存在。Executor 仍可指出缺少機制而補查。
6. **超大必要規則保留且允許續取。** 不把硬截字當成功。若必要規則群組連最低上下文都放不下，回傳可恢復的容量不足與續取入口；可依完整子規則分頁，但未齊前不得執行依賴它的機制。續取可在現有工具循環進行；若無法安全建立完整裁決上下文，就明確暫緩，請求聚焦行動或校閱拆分。不得靠跨回合模糊記憶當成已讀完整依據。
7. **長期團跨章資料仍受授權。** 當前允許章節與持久已揭露事實分別索引；舊 NPC／線索只有在現行權限允許時可讀。依賴不能自動開放未解鎖章節；不可存取的內容只回報安全原因與數量，不洩漏私有標題或 ID。Continuation token 綁定劇本、版本、查詢、角色／權限及相關時間線，權限或版本變更即失效。
8. **避免把效能問題移到匯入或記憶體。** 儲存／索引分批處理；只載入命中的記錄與必要相依，不能每次全圖 BFS 或預計算每個 root 的完整關聯副本。設定獨立且明確的檔案大小、批次、總儲存及遍歷資源限制，超限回報可操作錯誤，不悄悄裁切內容。

例如：長期團有 300 頁、某 NPC 資料 20,000 字元，應完整保存；玩家只詢問其外貌時可取公開外貌，開戰時則取得該 NPC 的必要戰鬥規則。若某例外條件在另一個尚未允許章節，應回報裁決依據不足，不能為了湊齊資料而解鎖該章。這是預期行為例，不是已完成的效能實測。

## 5. 內附網頁 AI 指令

匯出檔須提供以下可複製指令，且有中英兩版。這是提議的整備格式，不是目前 v3 匯入器的操作承諾：

> 請依附件整備格式與範例，忠實將來源單元翻譯為繁體中文。這不是摘要或重新創作。保留 export_id、batch_id 與提供的單元 ID，只填可編輯欄位。不要計算頁碼、hash 或字元位置。 不要為符合遊戲輸入字數而壓縮或刪掉翻譯；過長時依單元分批回傳，完整內容仍須保留。保留所有機制數值、觸發、費用、限制、例外與後果。規則必須附精確原文引述與單元 ID。visibility 只允許 public 或 kp_only；kp_only 的 public_text 必須留空。原文損壞或不明確處寫入 uncertainty，不得從其他版本或記憶補寫。回傳可下載 Markdown 檔，內含恰好一個整備 JSON 區塊。開始前回報單元清單與分批計畫。若無法處理全部單元，回傳明確標記的部分批次並列出未完成 ID，不要宣稱完成。

另附包含全部必填欄位與一條引述規則的合法合成範例，明確註明範例 ID 不是真實來源 ID。說明下載檔須先放進伺服器 IMPORT_DIR，再使用 Help；網頁 AI 不能直接呼叫 bot 匯入指令。不假設特定網頁產品功能或輸出長度保證。

### 匯出完成訊息必須直接顯示提示詞

成功匯出後，Help 與文字指令的回覆都須在提供 MD 附件／既有下載方式的同一則完成訊息中，直接顯示以下可複製提示詞；不能只藏在 MD、log、按鈕說明或另一個說明頁：

```text
請依附件內的整備指引完成繁體中文翻譯，回傳可匯入的 Markdown 檔；若需分批，請列出尚未完成的部分。
```

訊息順序：匯出成功與檔名 →「將 MD 上傳至網頁版 Gemini／ChatGPT，並貼上以下提示詞」→ 提示詞文字區塊 →「完成後下載 MD、放入 imports，再透過 Help 選檔匯入」。提示詞必須是可直接選取複製的文字，不要求使用者先開附件閱讀才能找到。多批次匯出仍在完成回覆中顯示一次提示詞，並列出批次清單與目前進度。

沿用 KP 匯出權限及私人附件傳送路徑；公開訊息不得附完整劇本或私人伺服器路徑。若平台需要分開傳送附件與文字，授權使用者收到的完成回覆仍須直接可見提示詞。匯出失敗不得顯示成功或提供無效下載入口。

## 6. 驗證報告與操作流程

彙整彼此獨立的失敗，不在第一筆錯誤就停止。報告有上限（提議最多 100 項，附總數／省略數）；前置條件不成立時跳過相依檢查。JSON 語法錯誤提供行／欄位置；不合法的記錄形狀不得讓深層驗證器崩潰。

每項包含代碼、嚴重度、記錄 ID、單元 ID、欄位路徑、有界的預期／實際值與修正建議。建議代碼：SOURCE_METADATA_MISMATCH、UNKNOWN_UNIT、MISSING_FIELD、INVALID_VISIBILITY、RULE_EVIDENCE_MISSING、AMBIGUOUS_QUOTE、COVERAGE_GAP、STALE_EXPORT、PROJECTION_DEFERRED、REQUIRED_EVIDENCE_UNAVAILABLE、RESOURCE_LIMIT。投影暫緩是可恢復狀態，不等於翻譯無效。詳細報告與來源片段限 KP 存取；公開回覆只提供安全摘要，不暴露私人路徑或原文。

保留 Help 授權、操作者檢查及檔名選擇。匯入先預檢，再保留未完成草稿、回傳校對報告，或儲存待校閱版本。預覽／核准／選用維持明確步驟。匯入失敗不改變現有遊玩內容。完整報告可由授權流程下載，與相同匯出包一起交回外部 AI 修正。

## 7. 流程與既有介面

```text
Help 匯出 -> export_template -> 可信任來源單元登錄
  -> MD 指令＋範例＋批次
  -> 使用者上傳網頁 AI -> 翻譯 MD -> 伺服器 IMPORT_DIR
Help 匯入 -> 授權＋選檔 -> 格式分派
  +-> 舊 schema v3 -> 改善診斷＋既有驗證
  +-> authoring v1 -> 查登錄資料 -> 批次／引述驗證
       -> 未完成草稿／校對報告
       -> 完整合併 -> 編譯 v4 -> 驗證來源／覆蓋／儲存資源
  -> 原子儲存待校閱版本 -> 私人預覽 -> 核准 -> 選用
遊戲 -> 授權來源索引 -> 合併必要證據 -> 依 token 預算取用
  -> 完整依據：裁決／敘事
  -> 必要依據未齊：明確續取／原文補查 -> 驗證後再裁決
```

實作邊界：`app/scenario_templates.py` 負責匯出／匯入協調與版本化儲存；純整備驗證／編譯應放在獨立模組。`app/scenario_projection.py` 需支援 v4 的有界投影與依據完整性回報。`app/help_actions.py` 與劇本指令處理器透過現有授權提供檔案／報告。RAG 查詢須依版本讀取已編譯 v3／v4 記錄，不處理整備草稿。v4 需搭配 Executor 的缺漏／續取工具契約，不能只改匯入驗證。

## 8. 相容性、測試與驗收

維持合法舊 v3 匯入、已核准版本及英文後備。v3 不默默重新編譯；明確轉換為 v4 時重新驗證與校閱。快取鍵須納入 schema／compiler／切分／權限／預算版本，舊預展開快取不得誤用。不自動把壞掉的 v3 檔解讀成 authoring v1。此次 Gemini 產出應得到多項有用診斷，不能只補來源欄位就升為已核准。

必要測試：
1. 合成無標題多頁來源可匯出可處理、確定性的單元，精確覆蓋且登錄映射穩定。
2. Unicode 位置、重複引述、跨頁條件、僅上下文文字、重複 ID 與跨章節關聯。
3. 合法整備格式匯出／填寫／匯入往返，編譯 v4 並保留規則數值與隱私。
4. 缺欄位、all 可見範圍、KP／公開衝突、字串規則、越界頁碼、過期／缺失登錄與錯誤 JSON。
5. 部分批次、冪等重送、衝突取代、原子儲存失敗與啟用版本保留。
6. 報告上限、授權與公開回覆不含私人原文。
7. 舊 v3 匯入／核准及既有中文／原文檢索回歸測試。
8. 提示詞／範例格式驗證，避免出貨範例與匯入器不同步。並測試 Help／文字指令的匯出成功回覆直接包含上述完整提示詞及有效附件／下載入口；涵蓋多批次、失敗回覆與私人傳送，確保使用者不必打開 MD 才找得到提示詞。
9. 300 頁以上合成長期團、多章重複 NPC、20,000 字元記錄及超過 12,000 字元關聯均可完整保存；匯入不因舊投影上限失敗。
10. 巨大與循環相依圖、必要規則超出 token 預算、未知適用條件、續取中版本／權限變更，均不洩漏章節或錯稱依據完整。
11. 比較短劇本與長期團的輸入 token、工具／LLM 次數、取用耗時、整回合耗時、必要規則召回與裁決正確率。測試中尤其驗證護甲、能力、觸發、費用及次數限制，不只確認找到 NPC 名稱。

使用模擬本次失敗的小型合成測資，不提交使用者完整劇本或 log。之後經明確授權可做網頁 AI 易用性試跑：記錄完成單元、匯入次數、診斷、遺漏與人工修正。核准此設計不代表授權付費 API 試驗。效能驗收：遊戲中不固定新增 LLM 呼叫；正常案例先由本地程式合併必要依據，盡量一次供給。超大或不明確案例可能增加續取與 LLM 往返，必須如實量測，不能承諾所有長劇本與短劇本同速。匯出／匯入耗時與翻譯耗時分開量測。

## 10. 實作結果與操作限制

- PR #94 的 `export_template` 原本匯出 authoring v1；後續三檔方案已改為 v2。`export_legacy_template` 保留 v3 相容性測試入口。新工作檔不要求外部 AI 填頁碼、hash 或來源位置。
- 每個來源單元以 4,000 字元為切分上限，優先沿段落／換行；每批目標 8,000 原文字元。它們是定位單元，不保證語意完整。相鄰上下文只作參考，跨單元條件仍須一起翻譯並明確關聯。
- 登錄資料與分批草稿位於劇本 variants 目錄的 `exports/<export_id>/`。預設資源限制為單檔／合併草稿 20 MB、20,000 筆記錄、每劇本 100 組匯出或 200 MB 匯出資料；超限明確報錯。草稿不自動過期，管理者需封存不再使用的匯出；清除劇本會一併清除。
- 同一原文父單元可合併多個 unit_ids（最多 100 個）；跨父單元須拆成獨立記錄並建立關聯。每個規則欄位目前接受一筆唯一精確引述；多筆證據回報 RULE_REPRESENTATION，要求拆成完整子規則，不猜測位置。
- 相同批次重送不重複建立版本。修改既有批次須在 JSON 明確填 `replace_batch: true`。缺單元只保存草稿；完整來源與規則驗證通過才儲存 v4 待校閱版本。uncertainty 或數值／否定疑點仍會阻擋核准。
- v4 冷啟動讀取一次有檔案資源上限的 records 並建索引；熱路徑重用快取。沒有逐筆資料庫串流儲存，仍受上述儲存上限約束。檢索只展開命中根節點的必要相依，最多 128 個節點，不為每個根節點預建完整圖副本。
- conditional 關聯目前一律保守視為必要，不由模型推測條件不成立。沒有結構化 rules 的非背景記錄，其文字視為必要依據；有 rules 的記錄優先帶完整規則，再取相關描述片段。這需要 KP 校閱確認機制已完整結構化。
- `SCENARIO_RETRIEVAL_TOKEN_BUDGET=6000` 是 token 預算；`SCENARIO_CONTEXT_TOKEN_CEILING=32000` 是部署設定的保守容量，不宣稱是模型規格。輸出預留 4096、安全餘量 2048；使用者應按部署模型調整。Executor 搜尋時扣除實際提示、工具、歷史、當前輸入及已取得工具結果；原有 provider 准入仍執行。
- 經典 v3 維持舊投影行為。v4 中文零命中仍補查目前允許章節原文；已知必要依據不足則明確標記，可由 Executor 要求原文。無關搜尋成功、或原文命中本身，均不能清除已知依據不足。此時同一工具執行器保守阻擋狀態變更及擲骰，待相同根記錄的完整依據取得或回合暫緩。
- 續取識別僅存於本程序有界快取（最多 128 筆），綁定群組、時間線、操作者／角色、劇本版本、章節、索引與查詢；重啟後失效。分頁不累積成虛假的 complete；單條不可拆規則仍放不下時，必須聚焦或校閱，不能無限續取。
- Help 與文字匯出共用處理器，完成私訊直接顯示指定提示詞與全部檔案路徑。沿用本機伺服器檔案方式，沒有新增 Discord 通用檔案附件傳送 API。詳細校對報告是 imports 中的私密 MD，路徑私訊 KP；公開回覆不帶原文或伺服器路徑。模板管理明確限 KP／Keeper，不因一般劇本管理開放設定而解除。

### PR #94 審查修正

檢索准入與 OpenAI 請求共用歷史選取，已裁掉的持久化歷史不再占用檢索額度；其他供應商仍計入完整歷史。續取只認定經中繼資料預算調整後實際交付的連續片段，後續頁累積依據，必要片段齊全才解除相同根節點的行動暫緩。識別保存原始根節點，除既有權限、版本與查詢外，也綁定歷史及結果數量。過大的必要片段不能跳過，也不能用後續片段宣稱完整。
