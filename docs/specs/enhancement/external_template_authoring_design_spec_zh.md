# 外部 AI 中文模板整備與匯入診斷

[English](external_template_authoring_design_spec.md)

## 狀態與範圍

分類：`enhancement`。狀態：**提案，尚未實作**。基準：`main_v2` 的 `c05e152`（2026-09-27）。此提案延伸 PR #83，保留原文依據、章節隔離及核准後才能啟用的要求。

此分支僅包含設計文件。實作及遷移測試完成前，現行匯入格式仍是 schema v3。

## 1. 已觀察失敗與原因

回報的《鬼屋》匯出只有一個來源單元 `chapter-01-u1`，涵蓋 PDF 位置 1–27，共 71,612 個 Unicode 字元。匯出 hash 與目前劇本一致。Gemini 回傳四筆記錄，沿用同一來源 ID，卻改寫頁碼（包含 28–40 頁），並刪除 `source_spans` 與 `type`。另有不支援的可見範圍 `all`、規則欄位使用一般字串，以及 KP 專用記錄帶公開內容等問題。

唯讀驗證重現頁碼／章節錯誤；僅在記憶體中修正頁碼後，下一個錯誤為缺少 `source_spans`。原檔與正式狀態均未修改。提供的 profiler 未捕捉匯入驗證器，不能據此量測匯入耗時。

`_blocks()` 辨識 Markdown 一、二級標題。這份解析來源缺少可用的該層級標題，整章因而成為一個單元。簡短匯出說明接著要求外部模型同時切分語意、計算位置、保留來源，並從空陣列推測格式。匯入器只回報第一個籠統錯誤。拒絕不合法內容是必要的，但整備契約與診斷需要改善。

## 2. 目標與非目標

1. 使用者將匯出的 MD 上傳網頁 AI、貼上內附指令、下載完成的 MD，再使用現有 Help 匯入按鈕。
2. 程式負責 hash、頁碼／章節映射、來源位置與覆蓋率計算；外部 AI 負責忠實中文翻譯與明確的規則／原文引述。
3. 儲存匯入候選前提供可操作的驗證報告；預覽、核准與啟用維持分離。
4. 遊戲中重用預備內容，不固定新增 LLM 往返，也不新增翻譯 API 依賴。

不包含：自動背景翻譯、瀏覽器自動操作、把摘要視為完整覆蓋、猜測缺漏規則、默默修正不明確的來源比對，或在本次文件工作中翻譯正式劇本。改善匯出包裝不能修復錯誤的 PDF 閱讀順序；損壞段落須保留疑點，指向 PDF 校閱／重新解析。

## 3. 匯出包與來源單元

提議的匯出內容包含：可複製的網頁 AI 提示詞、不可變來源片段與單元 ID、可編輯翻譯記錄、一筆完整合成範例、欄位限制與完成檢查表。範例放在匯入 JSON 之外，避免誤匯入。

在劇本庫保存不可變匯出清單，包含 `export_id`、來源／章節 hash、整備格式版本與切分版本。精確文字位置與單元 hash 由伺服器保存；匯入 MD 不能重新定義映射。重新解析或改變切分方式須建立新匯出識別；缺少或過期的識別要求重新匯出。

有可靠場景／標題資料時沿用；缺少標題時，使用保留精確原始位置的確定性頁面／段落單元，並標記不透明或損壞段落。這些是來源定位依據，不表示規則在頁尾結束。另附帶 ID 的鄰近來源上下文；條件／後果跨單元時須明確建立關聯。只作上下文的內容不算已翻譯覆蓋。

編譯父層保留既有 `_blocks()` 來源 ID；新的較小單元 ID 映射到父層文字範圍，不改變舊 v3 解讀方式。整備記錄跨越父層時，編譯器可輸出多筆互相關聯的 v3 記錄。不能只為符合大小限制而切斷規則；未處理的跨單元規則阻擋核准。

初始可設定的包裝目標為每批最多 8,000 個原文字元；完整單元可超過目標，但須明確警告。這是待驗證的易用性目標，不是量測後的最佳值，也不是遊戲投影上限。每批有識別、預期單元清單及進度，允許分批回傳而不遺失未完成工作。既有 6,000／12,000／18,000 遊戲投影限制仍為最終依據。

## 4. 整備格式與編譯

新增獨立的 `authoring_version: 1` 封套，不把它偽裝為 `schema_version: 3`。封套必填 `export_id`、`batch_id`、`records`。整備記錄包含唯一 `id`、`unit_ids`、`type`、`name`、`aliases`、`keywords`、`visibility`、`public_text`、`kp_text`、`rules`、`related_record_ids`、`uncertainty`。可編輯資料不含執行期來源欄位，改由匯出清單重建。

規則保留目前五種欄位：trigger/check/success/failure/exceptions。每個已填欄位包含 `text`，以及帶有 `unit_id` 與精確 `source_quote` 的 `evidence`。編譯時要求引述在指定單元中精確且唯一；多處相符須釐清或重新切分。不能模糊比對或虛構位置。需要多筆引述時，編譯成多筆完整規則，或回報無法表示；不能擴大引述納入無關文字來通過驗證。

每個分配的來源單元都須完整翻譯，或保留會阻擋核准的未解決狀態。單元覆蓋只是結構覆蓋，不證明翻譯忠實。數值／否定檢查、規則引述、私人預覽與校閱仍然必要。所有疑點持續保留，直到明確解決。

編譯器由登錄資料產生可信任的 v3 頁碼／章節／位置欄位，重建原文片段、映射依賴，再執行既有 v3 驗證與投影限制。可推導明確的來源資料，但不能修補無依據的宣稱、翻譯缺漏內容或默默改變隱私。KP 專用記錄帶公開文字應報錯，不自動決定公開。

部分批次草稿與可遊玩版本分開儲存。完整且驗證通過的合併內容，才透過原子儲存成為待校閱候選。相同批次重送須具冪等性；ID 衝突或改寫已提交內容須明確取代並重新驗證。部分匯入不得改變啟用版本。

## 5. 內附網頁 AI 指令

匯出檔須提供以下可複製指令，且有中英兩版。這是提議的整備格式，不是目前 v3 匯入器的操作承諾：

> 請依附件整備格式與範例，忠實將來源單元翻譯為繁體中文。這不是摘要或重新創作。保留 export_id、batch_id 與提供的單元 ID，只填可編輯欄位。不要計算頁碼、hash 或字元位置。保留所有機制數值、觸發、費用、限制、例外與後果。規則必須附精確原文引述與單元 ID。visibility 只允許 public 或 kp_only；kp_only 的 public_text 必須留空。原文損壞或不明確處寫入 uncertainty，不得從其他版本或記憶補寫。回傳可下載 Markdown 檔，內含恰好一個整備 JSON 區塊。開始前回報單元清單與分批計畫。若無法處理全部單元，回傳明確標記的部分批次並列出未完成 ID，不要宣稱完成。

另附包含全部必填欄位與一條引述規則的合法合成範例，明確註明範例 ID 不是真實來源 ID。說明下載檔須先放進伺服器 IMPORT_DIR，再使用 Help；網頁 AI 不能直接呼叫 bot 匯入指令。不假設特定網頁產品功能或輸出長度保證。

## 6. 驗證報告與操作流程

彙整彼此獨立的失敗，不在第一筆錯誤就停止。報告有上限（提議最多 100 項，附總數／省略數）；前置條件不成立時跳過相依檢查。JSON 語法錯誤提供行／欄位置；不合法的記錄形狀不得讓深層驗證器崩潰。

每項包含代碼、嚴重度、記錄 ID、單元 ID、欄位路徑、有界的預期／實際值與修正建議。建議代碼：SOURCE_METADATA_MISMATCH、UNKNOWN_UNIT、MISSING_FIELD、INVALID_VISIBILITY、RULE_EVIDENCE_MISSING、AMBIGUOUS_QUOTE、COVERAGE_GAP、STALE_EXPORT、PROJECTION_LIMIT。詳細報告與來源片段限 KP 存取；公開回覆只提供安全摘要，不暴露私人路徑或原文。

保留 Help 授權、操作者檢查及檔名選擇。匯入先預檢，再保留未完成草稿、回傳校對報告，或儲存待校閱版本。預覽／核准／選用維持明確步驟。匯入失敗不改變現有遊玩內容。完整報告可由授權流程下載，與相同匯出包一起交回外部 AI 修正。

## 7. 流程與既有介面

```text
Help 匯出 -> export_template -> 可信任來源單元登錄
  -> MD 指令＋範例＋批次
  -> 使用者上傳網頁 AI -> 翻譯 MD -> 伺服器 IMPORT_DIR
Help 匯入 -> 授權＋選檔 -> 格式分派
  +-> 舊 schema v3 -> 改善診斷＋既有驗證
  +-> authoring v1 -> 查登錄資料 -> 批次／引述驗證
       -> 未完成草稿／校對報告
       -> 完整合併 -> 編譯 v3 -> 驗證覆蓋與大小限制
  -> 原子儲存待校閱版本 -> 私人預覽 -> 核准 -> 選用
遊戲 -> 既有中文檢索 -> 必要時補查原文
```

實作邊界：`app/scenario_templates.py` 負責匯出／匯入協調與版本化儲存；純整備驗證／編譯應放在獨立模組。`app/scenario_projection.py` 仍為執行期大小限制依據。`app/help_actions.py` 與劇本指令處理器透過現有授權提供檔案／報告。既有 RAG 查詢只使用編譯後 v3 記錄，不處理整備草稿。

## 8. 相容性、測試與驗收

維持合法舊 v3 匯入、已核准版本及英文後備。不自動把壞掉的 v3 檔解讀成 authoring v1。此次 Gemini 產出應得到多項有用診斷，不能只補來源欄位就升為已核准。

必要測試：
1. 合成無標題多頁來源可匯出可處理、確定性的單元，精確覆蓋且登錄映射穩定。
2. Unicode 位置、重複引述、跨頁條件、僅上下文文字、重複 ID 與跨章節關聯。
3. 合法整備格式匯出／填寫／匯入往返，編譯 v3 並保留規則數值與隱私。
4. 缺欄位、all 可見範圍、KP／公開衝突、字串規則、越界頁碼、過期／缺失登錄與錯誤 JSON。
5. 部分批次、冪等重送、衝突取代、原子儲存失敗與啟用版本保留。
6. 報告上限、授權與公開回覆不含私人原文。
7. 舊 v3 匯入／核准及既有中文／原文檢索回歸測試。
8. 提示詞／範例格式驗證，避免出貨範例與匯入器不同步。

使用模擬本次失敗的小型合成測資，不提交使用者完整劇本或 log。之後經明確授權可做網頁 AI 易用性試跑：記錄完成單元、匯入次數、診斷、遺漏與人工修正。核准此設計不代表授權付費 API 試驗。效能驗收：遊戲中不固定新增 LLM 呼叫；匯出／匯入耗時與翻譯耗時分開量測。

## 9. 待討論決策

建議採用整備 v1 與執行期 v3 分離、權威來源資料由伺服器管理的方向。實作前討論批次大小與草稿保留政策。精確引述刻意採保守判定；重複或損壞段落須明確修正，不放寬為模糊比對。自動切分無法認證所有語意依賴均完整，未解決的邊界必須持續可見。

設計核准後才開始執行期實作。既有不合法翻譯可作草稿，重新對應與校閱屬另一項內容工作。
