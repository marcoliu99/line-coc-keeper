2. **Phase 1 inventory**：只盤點 image-visible locations，保留 exact label、floor/section、original labels、hint 與 evidence。Code 按 label+section 正規化重複項、產生穩定 unique IDs、排除家具。Location-only audit 確認原 inventory IDs，再 deterministic merge 新缺漏 locations；不允許整份 graph 重建。
3. **Phase 2 connectivity**：輸入原圖＋canonical inventory，輸出 entry／directed edges／compass／type／visual basis／evidence。新 location 必須以 missing_locations 回報；未知 target 不會變成 gameplay room。Only door/open_passage/stairs/explicit one_way 可建立 traversal；牆、相鄰、shared wall、距離不是已可通行的出口。牆可被玩家破壞是未來遊戲狀態變更，本輪不推測牆已打破或修改 movement。
4. **Targeted repair**：最多一個 patch，只接受 add_locations/remove_edges/add_edges/replace_edges/entry_update。錯誤以 missing_location／dangling_exit／unsupported_edge／unverified_entry／invalid_compass 等分類。只有 error-scoped edge／location 可改；無關 evidence 保留。每個 removal 需 image evidence＋reason；更改已驗證 evidence 另需 fresh evidence。Malformed 或越界 patch 整份拒絕；repair 仍失敗則 map 留 private。
5. **Deterministic builder/certificate**：Code 建立 rooms/exits/entry，檢查 target、compass 與既有 structural validator。未標示 entry 明確 unresolved／incomplete，不造 entry。最終 image audit 覆蓋所有 location／room／edge／entry，拒絕牆與不一致 traversal basis。Certificate 在 cache／publication boundary 重播 generation、inventory audit merge、connectivity、patch，核對 graph/image hashes，不能只靠 verified flag。Raw phases／inventory／connectivity／patch 留 private；公開 quality report 保留 status、counts、errors、hash 與 timing。
