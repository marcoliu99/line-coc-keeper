# Semantic topology discovery with deterministic publication proof

Status: implemented after explicit confirmation. Branch: enhancement/pdf-multicolumn-ingestion / PR #155. Supersedes the unapproved narrow-grammar proposal in pdf_haunting_source_topology_validation.md.

## Problem and trust boundary
The existing source-topology-v2 extractor recognizes fixed affirmative assertions. A grammar miss is neither a negative source assertion nor proof that topology is unsupported. The published legacy Haunting text on physical pages 10–12 suggests outer boards → explorable wall space → inner wall → Room 4. That text has column interleaving, no current PR155 quality provenance, and no certified room inventory. It is discovery input only, never topology authority. Do not reimport/reconstruct those pages or rerun map-image providers in this scope.

Separate three import-only stages: permissive candidate discovery; strict deterministic evidence binding; strict certification/publication. Keep existing regex extraction as a deterministic fast path. A matched assertion must not suppress discovery of other, unmatched assertions/windows. No discovery/model call occurs during gameplay, certificate verification, library read or runtime movement.

## 1. Bounded candidate discovery
Add a focused app/pdf_source_topology_discovery.py beside existing source topology code, not a generic plugin framework. The existing analysis_provider registry supplies its structured text-only analyze_text capability. No image/vision calls or new provider routing. Document text is untrusted data, never instructions. Model output proposes possible source assertions only; it cannot create rooms/edges/barrier states or invent location, breakability, direction, difficulty, HP/armor, hidden status or progression necessity. Confidence is diagnostic only.

Use coarse lexical cues and known location context to select bounded windows, not as an acceptance gate. Defaults: at most 3 consecutive physical pages/window, 12,000 Unicode characters/window, 4 windows/requests per import, and 8 candidates/window. Never concatenate nonadjacent pages or trim out intervening source text to manufacture continuity. Oversized evidence that cannot fit a contiguous window remains incomplete. Cache identical windows within the import. Config can disable semantic discovery or lower the finite budget; changing bounds cannot authorize weaker proof. Use request timeout and zero retries through provider-local text-analysis options, retaining existing callers' defaults. Separate source_topology_discovery_requests diagnostics from OCR, Docling, map-image and AI-repair counters.

Candidates have closed candidate/claim types, candidate-local barrier/location identifiers, ordered proposed segments, source kind, and individually cited assertions for start, each barrier, enterable intermediate, destination, ordering/continuity, and optional conditions. Each reference supplies physical page, absolute full-source Unicode offsets and exact quote/reference. Returned hashes, labels, confidence and evidence classes are never trusted: binder recomputes hashes/classes. Unknown fields and invalid/oversized structures fail closed. No candidate may hide a further supported barrier by truncating a chain.

## 2. Deterministic evidence binding
A pure public bind_candidate seam receives a candidate, source context and certified inventory. Check exact Unicode span/quote equality, page-marker membership, local source hash, canonical identity, bounded adjacency, and source provenance. Hashes alone prove text presence, not semantic entailment. Every assertion must additionally pass a role-specific deterministic proof rule: location reference, barrier/action assertion, enterable-space consequence, next barrier identity, destination consequence, explicit order/continuity, and any optional condition. These proof rules can recognize explicit narrative clauses across sentences/pages; they do not trust model-assigned roles, types, paraphrases or confidence.

Represent evidence classes as EXPLICIT, SUPPORTED, AMBIGUOUS and UNSUPPORTED. Initial certification accepts EXPLICIT only. Reserve SUPPORTED for a separately documented existing deterministic rule; no model judgement qualifies. Unrecognized paraphrases remain discovered candidates with EVIDENCE_INCOMPLETE/AMBIGUOUS, not SOURCE_UNSUPPORTED. Broad discovery intentionally exceeds what proof rules can safely certify.

Initial proof-rule families: (1) an explicit barrier removal/break condition whose consequence reveals/reaches an enterable space, paired with an explicit uniquely referenced inner barrier whose consequence enters a named destination; (2) successive explicit barrier-crossing clauses each naming its reached location. Preserve the existing full-assertion grammar recipe as another proof family. Recognizers inspect the original cited text and its bounded source context; they do not accept an LLM-generated normalized sentence as evidence. Different synonyms may be discovered without having a proof recipe; unsupported recipe coverage remains incomplete. These families require evidence for the same intervening structure and each action-to-result relation, not a generic bag of words.

Order requires explicit causal/continuation evidence joining the same structure/location, not just increasing offsets, repeated wall tokens, or proximity. Cross-page pronouns need a unique verified antecedent; competing spaces/barriers or interleaved reference ambiguity fail closed. Each barrier has independent evidence/identity. Named start/intermediate/end locations must bind uniquely to existing inventory, including source-supported floor/section disambiguation. Missing inventory is ENDPOINT_UNRESOLVED, never a new story room. An unnamed source_transit requires explicit enterability, no canonical name, stable evidence-bound hash, kind=source_transit and player_label="". Existing per-barrier progression, movement, discovery and fail-forward contracts remain unchanged. Fail_forward requires its own explicit source proof; no difficulty/tool/HP/armor/retry restriction is inferred.

## 3. Canonical authority and certification
Introduce a source context distinguishing legacy discovery text from validated final canonical source. Canonical eligibility must be derived by a deterministic factory from the actual final rendered pages plus current PR155 page-quality/provenance and extraction identity; it cannot be a model field, manifest content_hash match alone, or a caller-provided trusted=True flag. Check selected page text/hashes, physical page coverage/order, full rendered source hash, accepted source dispositions and absence of source-blocking reasons. Production importer builds this context only at its existing final-source gate. Library/cache verification derives equivalent context from stored ingestion provenance and exact scenario.txt/PDF identity. Missing legacy provenance means CANONICAL_SOURCE_UNAVAILABLE / AWAITING_CANONICAL_SOURCE, even if a candidate seems clear.

Certify only after canonical eligibility, all role proofs, unique endpoint binding, complete ordered segments and certified visual graph pass. Extend the existing source certificate with canonical-quality identity, accepted binding/proof hash and assertion evidence/order hashes. Preserve current visual Phase1/Phase2 and reading-order/OCR/source-publication rules. A source overlay alone cannot turn an unverified visual map into a certified map.

Persist accepted evidence proof separately from raw proposals in private ingestion provenance. Verification must replay canonical eligibility and the deterministic proof/builder without live model inference; re-running the old grammar alone is insufficient for semantic-discovered routes. A changed span/hash/order/barrier count/quality identity invalidates source certification and graph-bound runtime receipts. Strip all source proposals/overlays from independently reused visual proof; rebuild/rebind against the final book source. Keep old visual-only certification valid under its existing contract; old source overlays without the new proof contract fail closed.

Source topology/evidence-binding versions must advance (planned source-topology-v3). Extraction identity includes semantic discovery policy/version/config/provider-model identity and binding/canonical-quality versions. Review whether the new source trust contract requires multicolumn-v8 → v9; use the existing resume/cache identity policy and test it explicitly. Do not mechanically change the visual certificate version.

## Diagnostics and publication
Use closed private states: DISCOVERY_NONE, DISCOVERY_CANDIDATE_FOUND, EVIDENCE_INCOMPLETE, EVIDENCE_AMBIGUOUS, CANONICAL_SOURCE_UNAVAILABLE, ENDPOINT_UNRESOLVED, ORDERING_UNRESOLVED and CERTIFIED, plus provider/budget/invalid-reference reasons. AWAITING_CANONICAL_SOURCE describes candidate certification pending validated reconstruction. SOURCE_UNSUPPORTED requires an actual deterministic contradiction/unsupported claim, never grammar miss. DISCOVERY_MISSED_SUPPORTED_SOURCE is an evaluation diagnostic only when independently verified canonical reference evidence proves the missed route; it cannot be self-awarded by the model or inferred from an empty discovery result.

Uncertified proposals cannot alter visual graph, ordinary exits, source text or world state. Retain them as private audit data and expose sanitized counts/statuses/hashes only. Extend report sanitization for any new book-level or row-level discovery fields as well as map_analysis, so private windows/quotes/candidates cannot leak through the copied public report. Topology/map failure remains a derived warning and READY_WITH_WARNINGS; independently unsafe canonical source retains the existing hard block. Preserve existing graph quarantine rules at authoritative boundaries. No raw copyrighted source/model output is committed or exposed through public reports.

## Implementation and validation
Implemented source-topology-v3, semantic-source-proof-v1 and multicolumn-v9. The new canonical eligibility and replay contract changes accepted-page/draft identity; visual-only image-map-certification-v2 stays unchanged. Provider model identity is supplied through the common registry interface. Text requests use 30-second timeout/zero retries; a separate durable ledger inside the import budget preserves reservations and identical-window results without spending image allowance.

The closed candidate representation bundles each action/result assertion into `opening` then ordered `crossing` citations (physical page, absolute Unicode offsets, exact quote); the binder derives barrier types, endpoints, transit, order and hidden state from original clauses, never supplied normalized semantics/confidence. Initial proof recipes recognize explicit removal revealing an enterable space and subsequent uniquely referenced crossings, plus successive named-location crossings and an explicit hidden-route opening. Original grammar remains the fast path. Other wording is still discovered but remains EVIDENCE_INCOMPLETE/AMBIGUOUS. Explicit naming evidence blocks anonymous transit unless a named proof resolves inventory; uncertain continuation blocks partial certification. These conservative proof limits are deliberate, not a claim of real-corpus semantic accuracy.

The private accepted proof and canonical receipt are hashed into the source certificate and replayed without inference at library/cache boundaries. Public reports keep sanitized statuses/counts; candidate quotes and durable window payloads stay private. No OCR, Docling, visual extraction, gameplay or source publication gates were changed.

Real legacy Haunting p10–12: six existing source span hashes rechecked; manually supplied evidence candidate returns CANONICAL_SOURCE_UNAVAILABLE / AWAITING_CANONICAL_SOURCE, zero certified routes. No semantic or image provider was called, no canonical reconstruction or real discovery accuracy evaluation was performed. See pdf_semantic_topology_validation_results.json. Source/inventory revalidation remains separately required.
