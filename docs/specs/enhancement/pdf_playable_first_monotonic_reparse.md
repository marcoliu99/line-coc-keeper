# Non-blocking first import and monotonic reparse

## Contract
First import publishes trustworthy playable core. Classification candidates and unavailable enhancers are not authority or sufficient evidence to block. Unverified image content is quarantined before canonical composition, indexes, retrieval and topology extraction. Core reading-order defects, corrupted mechanics, evidenced unique required missing source and absence of a safe playable core remain blocking.

## Scope
Admission composition and deterministic reparse merge only. OCR, visual maps, certificates, topology extraction, runtime and rules remain unchanged. No book-specific rules. Physical page identities, source PDF hashes and source-role evidence identify content; no confidence publication.

## Merge
A published version is authority, including legacy entries. New uncertain content cannot replace it. Equal verified content is stable; differing verified content is a conflict retaining current authority. Independently validated additions may upgrade previously quarantined page/region/artifact identities. Certificates are replayed against the selected source, never rebound by a merge. Old certified maps and validated pregens are retained unless a validated replacement is compatible. A staged library transaction commits the complete merge atomically; failure preserves the published version. Live correction preserves timeline, investigator resources, checks, combat and location.

## Provenance and UX
Private provenance retains quarantine and source evidence. Public reports contain sanitized decisions, hashes and counts. Reparse diff records selected authority, unchanged/upgraded/conflict/deferred decisions, and previous version identity. Success remains success with warnings and existing reparse guidance. Reparse reports upgrades, no improvement or conflict without interrupting play.

## Validation
Regression-first public extraction/library/command tests cover unknown quarantine, core safety, authority exclusion, page and region monotonicity, feature additions, conflict, transaction failure and live-state preservation. Run pytest, ruff, mypy, compileall and diff-check, then Standards and Spec reviews. Real six-book validation uses original production caps and bounded authorized OpenAI requests. Haunting uses published-library reload/start regression only. Other five use fresh isolated first import and publication/reload/use/start where source-safe. A production reparse smoke demonstrates no downgrade/state reset. Unproven results remain PENDING, never represented as real success.

## Tradeoffs
First import may exclude unavailable non-core content. Positive core-source evidence can retain a blocking review. Reparse never resolves a source conflict through model preference or recency; conflicting current authority requires explicit source review.

## Implemented selection boundaries
New candidates require explicit verified authority and a matching source digest. Only the published side receives legacy authority. An entirely empty/art/credits document cannot substitute for playable core. Trusted short narrative source remains usable; uncertainty elsewhere is quarantined.

A PDF identity change defers page alignment rather than assigning old receipts to a new PDF. Private attempt history preserves each consumed candidate ledger without recursively copying history. Reparse index additions without artifact receipts are deferred. Pregen additions require exact names, literal mechanics and unambiguous single stat sets; a page containing multiple stat sets cannot bind one character to another character's values. Existing pools remain intact.
