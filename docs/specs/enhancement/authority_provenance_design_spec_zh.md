# 來源可追溯的世界權威與敘事連續性

[English](authority_provenance_design_spec.md) | [文件索引](../../README_zh.md)

## 狀態與問題

分類：`enhancement`。狀態：**backlog，等待整體設計確認**。依 `main_v2` 的 `7cef87c` 核對。

目前 `GroupState.log` 的玩家回合、KP 正典與核准更正多半只存 `role/content`；摘要與 Memory RAG 又把它們攤平成同一段文字。一次錯誤敘事因此可能被摘要或檢索帶回，變成下一次工具呼叫的假依據。`record_established_fact`／`record_clue` 目前不驗證來源，其紀錄也會進入 Scene Digest。無真人 KP 的更正裁決還能引用附近的 `log:N`；那只能證明「當時說過」，不能證明世界真相。

## 三層權威

| 層級 | 內容 | 能否授權有影響的世界事實或狀態變更 |
| --- | --- | --- |
| Authority | 當前已提交狀態、持久工具／事件收據、條件已成立的劇本依據、已驗證 fact／clue、真人 KP 明確正典 | 可以，但須符合時間線、受眾及來源範圍 |
| Presentation | 已送出的守密人敘事、NPC 台詞 | 不可以；仍保留玩家聽過什麼與日常感官連續性 |
| Claim | 玩家說法、場外異議、未驗證的模型推測 | 不可以；應保留並核對 |

劇本可預先記載隱藏或有條件的事件，但條件未發生時，不能宣稱玩家已發現。當前 state 高於舊的 Scene Digest；已驗證的歷史 digest 也不能覆蓋當前 state。`campaign_summary`、記憶片段與原始敘事只能幫助回想，不能獨立授權機制。

守密人仍以敘事為主。**物品存在／持有**與**劇情關聯**是兩個不同判定：普通日記或多出一本附帶日記可以被描述、由玩家取得並記錄持有，不因此變成劇本線索。只有劇本或已提交事件讓特定數量影響劇情時，數量才是必須維持的硬條件。閱讀附帶日記時可生成普通的氣氛文字，之後重讀也可以，但不能因此新增線索、必經提示、觸發或機制利益。bot 不應把它反覆暗示成必讀的關鍵線索；玩家指出這是 AI 自己誤加的重要性時，直接修正敘事，並讓摘要／記憶知道後來已更正。

物品可以有劇情用途，但不一定是線索。《The Haunting》開場由房東交給調查員鑰匙、地址與預付款；宅邸前門有一道鎖與另外四道門閂。這些鑰匙是有劇本依據的持有物，也可能是通行道具。原文沒有逐字配對哪把鑰匙開哪道鎖，因此守密人應依劇本與當前場景裁定用途，不得聲稱原文已明說配對，也不能讓每把普通鑰匙有同樣能力。即使確定能開前門鎖，那也是通行能力；只有揭露資訊時才另算線索。門閂是另一項障礙，鑰匙不會默默略過。相對地，地下室封閉房間的櫥櫃**裡面是腐爛的教會紀錄**；偵查成功後才指出**櫥櫃下方的一本日誌與一本典籍**。條件未成立時，不得宣稱調查員已發現兩本書。

AI 守密人可更正自己對劇本的誤讀，不能主動改寫劇本。已登記的真人 KP 助手可以明確覆寫劇本並留下 supersession；任何人都不能只靠文字覆寫已提交的骰子或資源結果。玩家可直接要求修正不影響機制的敘事，但不能只憑聲稱補一把鑰匙、改日記數量或移動角色。

## 資料與權威投影

- 保留 `state.log` 與玩家可見歷史。新紀錄包含 `record_kind`、`authority`、`turn_id`、`timeline_id`、受眾及可得的 fact/event 引用。玩家訊息是 claim，送出的守密人文字是 presentation。真人 KP 的明確輸入、工具已提交結果與 AI 回覆要分開標記。舊裸紀錄先標 `legacy_mixed`；只有能連到持久收據、核准更正或真人 KP 明確原文時才升格。
- 建立小型 `CanonicalFactRef`／事件投影，不做大型知識圖譜。已驗證 fact 具有穩定 ID、主體、必要時的數量／位置／身分欄位、來源類型與持久引用、可見受眾、時間線和驗證／失效狀態。劇本引用綁版本、record ID 與內容摘要；每回合的 `tool:N` 不能當永久來源。換版後重核劇本衍生事實，但保留已提交機制結果。
- 保留 fact/clue 工具的記錄與玩家更正彈性。沒有可驗證來源的新舊紀錄可供查看，標 `unverified`，但不能進正典投影或授權有影響的工具。來源 ID 存在仍不等於文字內容受其支持；可核對原文、型別化工具收據或真人 KP 明確正典才能升格。舊資料不直接刪除。
- 玩家可在場景沒有明確否定時，透過既有背包工具取得並持續持有普通附帶物件。已提交的背包事件只證明持有，不自動證明其與劇情有關的內容、線索地位、特殊武器傷害、開特定門的能力或劇本觸發。這些能力各需角色卡、工具結果、規則或劇本依據。玩家「現在拿起一件普通物品」與「聲稱上一回合已拿到關鍵鑰匙」必須分開。
- Scene Digest 只將可追溯的狀態欄位作為已驗證歷史；被複製進去的未驗證 fact/clue 不因 digest 而升格。按本回合需要與受眾投影權威。私人線索須有明確分享／揭露事件才改變受眾；偶然公開敘述不會自行解除私密性。
- Provider 必須明確投影 log 的來源標記。只在資料庫加欄位沒有作用：OpenAI／Anthropic 現在只送 `role/content`，Codex 則會收到結構化 history。兩個 Agent 都要看到一致的權威標籤與優先序，且 SDK 輸入仍須合法。

## 回合與更正流程

```text
劇本規則＋已提交事件＋真人 KP 明確正典
  → 按受眾篩選的已驗證權威投影
  → Executor 裁決、NarrationRequirements
  → Narrator 敘事及受限工具
  → DeliveryEnvelope 核對本回合必要事實與現存按鈕
  → 已送出文字只作 presentation 保存

玩家自然語言更正
  → 在移動／地圖變更前辨認為場外異議
  → 純敘事修正，或依來源核對的更正案件
  → 有真人 KP 交其裁決；否則 AI 依系統證據裁決
  → 核准後留下 supersession／合法機制修復
```

`NarrationRequirements` 傳遞相關權威事實、已提交事件、待檢定／Luck 控制、可用依據，以及僅針對有劇本／事件影響的型別化硬條件；不要求每回合重複所有正典或附帶物件。`DeliveryEnvelope` 只強制交付本回合應告知且對收件者可見的事實。確定能辨識的關鍵數量／位置／身分衝突、漏掉必要事實或按鈕，可由程式擋下；程式不保證讀懂任意散文。遇到已確定衝突，用已驗證事實與控制項組成保底回覆；未送出的模型草稿只供診斷，不寫成玩家歷史。不加固定 LLM 審稿。

明確的自然語言場外更正必須在既有移動解析之前攔下；語意不明時追問，不變更狀態。純感官措辭，或 AI 無依據地把附帶物件說成重要線索，可當回合直接修正，不另加一次 LLM 裁決，並記錄為敘事更正。對劇本線索、受約束數量、既有位置、資源或機制的爭議在核實前仍是 claim。保留 `/coc correct`。有真人 KP 助手時由真人裁決重要爭議；沒有時由 AI 守密人依系統持有證據走現有條件式裁決。`log:N` 只能證明曾說過，不能單獨證明世界真相。核准的重要更正須記錄被取代的內容與新來源；未解爭議不得贈與劇情資源或改動已提交機制。

## 摘要、記憶與舊資料

摘要輸入分開標示權威收據、已送出敘事與玩家主張；權威部分由 Python 從已驗證來源投影。`campaign_summary` 僅作對話／敘事摘要，舊摘要立即降為未驗證。摘要可保存氣氛、附帶物件與 NPC 曾說的話，不能把它們升格為無來源線索、受劇本約束的數量／位置或機制所有權。保留目前偶發的摘要呼叫，不新增一般回合呼叫。

Memory chunk 保留原話，另記 `memory_kind=conversation`、`authority=mixed`、來源版次、時間線與來源訊息資訊。檢索標頭改說「較早的對話」，不宣稱必然是已發生世界事實；舊 chunk 立即視為混合／未驗證。歷史整理只標記能由型別化權威證明的衝突，其餘仍待驗證；不刪玩家看過的 log。整理後依標籤重建對話摘要。核准更正使舊描述在權威投影中失效，但保留歷史原文。

## 四個獨立 PR

1. **阻止放大**：所有 log 寫入點加來源標記及 provider 投影；Executor／Narrator 共用優先序；修改記憶標頭、chunk 標記與摘要輸入；舊摘要／記憶立即降級。一般回合 LLM 呼叫拓撲不變；無來源 fact/clue 不再默默升格。
2. **正典投影**：持久來源引用與收據、fact/clue 驗證狀態、劇本條件與揭露語意、受眾限定的權威區塊及 `NarrationRequirements`。維持當前狀態與時間線檢查。
3. **硬事實交付**：`DeliveryEnvelope` 加已驗證引用與本回合必要事實、範圍有限的確定性檢查及安全保底。不用全文 regex 審稿或固定 LLM 審稿。
4. **更正與歷史整理**：自然語言場外入口先於移動解析、沿用真人／AI 裁決權限、持久 supersession、舊收據配對、衝突標記與摘要重建。保留 `/coc correct`。

每項各用獨立分支／PR並更新規格狀態與證據。PR1 不等 PR4 才降低舊摘要與記憶的權威。若一般回合 provider 呼叫數增加，須量測並審查。

## 驗收

- C01–C03：《The Haunting》寫明地下室封閉房間的櫥櫃**內**有腐爛的教會紀錄；偵查成功才發現櫥櫃**下**一本日誌與一本典籍。Narrator 若說錯種類、數量或位置，下回合 Executor／Narrator 仍依來源與已提交的發現條件；偵查成功前不得說玩家已發現日誌和典籍。
- C04：玩家無依據地說「我有鑰匙」，不能補背包或開門。C05：NPC 否認日誌或典籍只算台詞。
- C06：真人 KP 明確覆寫可取代舊描述；AI 守密人不能自行改寫劇本。
- C07–C08：受污染的舊摘要／記憶可作對話歷史檢索，但不能覆蓋權威或授權工具。
- C09：不影響腐木味等無機制感官連續性。C10：一般回合 LLM 呼叫拓撲不變，條件式更正裁決另計。
- C11：提到「上樓」的場外糾正在核對前不改位置。C12：私人 fact 不公開，只有已提交揭露事件能改受眾。
- C13：劇本重建索引或換版會使舊劇本引用待重核，但不重播機制。C14：Narrator 失敗時，必要 fact／待處理控制仍由確定性交付保留。
- C15：玩家可取得一本額外的普通日記，但它不會變成劇本日誌或典籍，也不會揭露兩本書的內容或改變發現條件。C16：bot 誤暗示普通日記很關鍵時，玩家自然語言更正後不再將其推為劇情主線，不增加固定審稿呼叫。
- C17：附帶物件可登記背包，但劇情與機制能力仍待依據；斧頭不憑空取得自創傷害，普通鑰匙不直接打開特定鎖門。
- C18：閱讀額外的附帶日記，包含之後重讀，都可有一致的氣氛敘事，但不默默新增劇本線索或推動劇情。
- C19：開場房東交付的鑰匙是有劇本依據的持有物；場景裁定若確認其中一把適用，可用於前門鎖，但內側門閂仍另行處理。鑰匙不因可通行就被標為線索，普通附帶鑰匙也不繼承同一用途。

## 非目標與界限

不刪對話、不縮短故事、不禁止日常感官創作、不讓摘要成為權威、不讓玩家聲明自動成正典、不加固定 LLM 審稿。來源引用只能證明「引用了哪裡」，不能保證任意改寫在語意上完全受支持；只讓可核對內容進入型別化權威，其他爭議走更正流程。確定性硬事實檢查刻意只處理一部分衝突。

## 已確認的紀錄邊界

保留 `record_established_fact`／`record_clue` 供遊戲與自然語言更正使用。無來源內容先標 `unverified`；若只是無礙劇情推進與機制的敘事連續性，可以保留描述，但不得據此確立關鍵線索、劇情資源或劇本限定的數量／位置，也不得授權有劇情或機制影響的工具呼叫。先前提到「教會紀錄」只證明守密人曾這樣說，不能因此認定文件是必找線索；普通附帶物件無須因此被禁止。
