# Gameplay workflow

[繁體中文](gameplay_zh.md)

## Prepare a game

Upload a scenario PDF or choose a library scenario through /coc help. Role cards use role_ text/Markdown uploads; externally localized scenario workbooks use the separate template export/import/preview/approve/use flow. Source and chapter changes can invalidate templates.

## Characters and start

Use /coc pregens and /coc usepregen when the scenario provides investigators. Otherwise use /coc pc or /coc create and allocate skills. Keep printed/verified Luck; blank Luck requires the owner’s /coc luck roll. Unreadable core attributes need correction before claiming that card. After readiness checks, /coc start uses the scenario opening or generates a supported fallback. Ordinary text does not advance the game before start.

## Actions and checks

Describe actions in ordinary messages. Keeper normally registers a check and the owner rolls with the button or /coc check; any player may toggle group /coc autoroll on|off, affecting new checks only. Choose mutually exclusive defenses explicitly. Legal affordable useful Luck upgrades are offered without a near-miss-only rule; /coc luck skip declines. Settled dice are never rerolled because narration failed.

## Combat, maps and privacy

Combat uses DEX initiative, separate enemy instances and formal damage/effects. /coc combat status shows current order; /coc away and /coc back manage absence. Map tracking is optional: /coc where, /coc enter and /coc leavemap operate supported maps. Without a map, movement still follows scenario evidence. Private handouts/goals are sent to authorized recipients; allow DMs if you expect private delivery.

## Purchases and corrections

Travel to a supported shop before buying. Lifestyle purchases record acquisition; cash purchases require a confirmed quote and sufficient recorded funds. /coc purchases shows balances/quotes/receipts and /coc purchase ID confirms payment. /coc correct reports a Keeper message outside the game; reports need current-timeline receipts and do not themselves impose a mechanical hold. KP adjudication can approve, reject or scope a hold.

## Help and administration

Help buttons execute commands with forms/lists where needed. /coc sheet and /coc status inspect state. KP Assistant is an independent OOC agent; authorized /coc sudo delegates allowed player operations. Checkpoints restore into an isolated timeline. /coc end ends the game, while /coc newgame resets it; reusable manual-card assets are retained by their persistence policy. See the command reference for exact permissions and syntax.
