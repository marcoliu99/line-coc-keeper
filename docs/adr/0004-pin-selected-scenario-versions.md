# Pin the selected scenario version

A group must keep the scenario version it explicitly selected even when another group reparses the same logical scenario. We chose immutable published versions and explicit, coherent switching of text/images/maps and character/NPC source evidence rather than automatic following of latest, because source drift changes rulings and rollback evidence without a game decision. This accepts version-storage and migration work; missing historical evidence must not be represented as proof that a game used latest. The operator subsequently chose to remove old scenarios before rollout, excluding historical-source migration; the cleanup boundary must also account for references retained in games, drafts and checkpoints. This does not permit substituting latest for a missing reference in newly created data. Current combat, checks and Luck finish before switching versions; continuing obligations need explicit compatibility handling. The detailed future-obligation policy remains subject to the ongoing interview.
