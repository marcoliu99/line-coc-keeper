# External Chinese template reference review

## Scope and evidence

Reviewed user-provided PDFs locally, with text extraction plus visual checks of
representative multi-column rule pages. Raw extraction was not treated as a faithful
reading order. No scenario PDFs, complete translations or extracted source text are
committed with this review.

| Source | PDF pages | Visually inspected examples | Template requirement |
| --- | ---: | --- | --- |
| The Haunting, trimmed | 27 | PDF 10-11 and 15 (printed 26-27 and 31) | A scene's stairs/check/Push consequences, floating-weapon rules and creature defenses reference different passages; preserve full rule dependencies and distinguish PDF positions from printed page labels |
| Dead Boarder | 32 | PDF 11, 16 and 18 | Investigation, possessions, conditional clues, combat tactics and defensive exceptions must remain distinguishable; scenario narrative may refer to a separate stat block |
| The Lightless Beacon | 43 | PDF 21, 23-24 (printed 20, 22-23) | Creature ability description continues across pages; keep trigger, resistance, duration, limits and armor exceptions together; preserve encounter scaling rather than treating one stat block as one fixed enemy |
| Doors to Darkness Pre-Generated Characters | 11 | PDF 2 (first investigator), text/layout scan of all investigator pages | Age and identity, numeric skills, free-form background, intentional blanks, equipment, cash prose and player notes need distinct authoring treatment |

Several extracted pages interleave two columns or mingle adjacent stat labels and
numbers. A valid PDF page reference cannot by itself prove that a translation's source
text was correctly extracted. External preparation must inspect the page image before
approving a suspicious row. Image-only character pages are not empty content.

## Additional official campaign references

These are publicly available descriptions/reference materials, not a review of the
complete commercial campaign texts. Accessed 2026-09-27.

- [Masks of Nyarlathotep, Chaosium](https://www.chaosium.com/masks-of-nyarlathotep-slipcase-set/):
  the official description permits investigators to follow international leads in their
  own order. Design inference: represent clue destinations and revisit conditions;
  do not assume chapter number is play order.
- [Masks Keeper Reference Booklet](https://www.chaosium.com/content/FreePDFs/CoC/CHA23153%20-%20Masks%20of%20Nyarlathop/CHA23153%20-%20Masks%20of%20Nyarlathotep%20-%20Keeper%20Reference%20Booklet.pdf):
  the opening character pages distinguish regular combat and Pulp alternatives.
  Design inference: edition/rules-mode and profile identity must prevent accidental
  mixing of alternative stats. A campaign's publication edition is distinct from
  the Call of Cthulhu rules edition.
- [Horror on the Orient Express, Chaosium](https://www.chaosium.com/horror-on-the-orient-express-pdf/):
  the official description includes multiple destinations and optional scenarios in
  different historical settings, plus a calendar and handout resources. Design
  inference: retain setting era, travel/event timing, document identity and optional
  episode links rather than treating all content as one present-day location.
- Official handout packs: [Masks](https://chaosium.itch.io/masks-of-nyarlathotep-handouts-pack)
  and [Orient Express](https://chaosium.itch.io/horror-on-the-orient-express-handouts).
  They are supplemental evidence, not substitutes for complete scenario rules.

## Authoring contract

    original source + page images
      -> externally checked reading order / complete source units
      -> source-bound editable template
      -> externally translated prose + complete rules + glossary
      -> import validation -> KP review -> approved retrieval variant

### Source unit and narrative

Keep stable source ID, chapter ID, PDF page positions, heading and the full source
excerpt generated by the exporter. Record printed page labels separately when needed.
Keep public narrative and KP-only material separate. A rule block should include all
of its prerequisites, check, outcomes, resource cost, usage limit, duration, exceptions
and source references. Unknown is not false, zero, unrestricted, or permission to
invent a missing rule.

The current schema supports `trigger`, `check`, `success`, `failure`, `exceptions`
with full Chinese text plus an exact `source_quote`. Express costs, timing, uses per
round/encounter and follow-up effects in these complete text fields. Multiple related
rules can be separate entries in `rules`; do not reduce a creature to HP alone.
Additional normalized numeric ability fields are not introduced in this revision.

`related_source_ids` preserves explicit dependencies, but does not grant chapter
access. Long-campaign graphs need separate visibility/unlock policy: a discovered
lead to another country does not make every secret in that chapter public. The current
selected chapter-window policy is unchanged; this review does not claim full arbitrary
campaign navigation is implemented.

### Human editing and importer compatibility

The new command `/coc scenario template export SCENARIO_ID` writes a private workbook
into the configured server import directory and sends the KP its path. It calls no
translation/embedding API. Each generated record includes source metadata and blank
Chinese fields. Copy the file for external preparation, edit its records JSON, then
place the completed `.md` back in the import directory and use `template import`.
The bot reports a server path; it does not yet attach the workbook to Discord.

The existing parser requires a JSON block, not arbitrary Markdown headings. Blank
workbooks intentionally fail validation; they cannot be activated as untranslated
variants. Do not modify IDs/hashes to force an out-of-date translation to import.
Exporting again creates a new file and never overwrites partially completed work.

Current source segmentation uses extracted Markdown headings. If extraction produces
one huge unstructured chapter, export keeps that unit intact. An externally translated
large unit can be imported, but retrieval may return too much text. Source-unit curation
and support for multiple semantic records per source unit remain follow-ups; do not
pretend a PDF page splitter or this exporter solves those issues automatically.

### Role cards: open prose and actual mechanics

Use [the role-card template](references/role_card_template.md) for `role_` uploads;
this format is separate from scenario records JSON.

- Age accepts the original wording, including approximate ages. It is retained in
  descriptive metadata, not used to apply another round of aging adjustments.
- Appearance, traits, beliefs, people, places, possessions, background and player
  notes remain multi-line prose. Preserve the distinction between an absent field
  and a deliberately blank field; never populate personal details automatically.
- A treasured possession is not automatically the starred key connection. Only
  `【關鍵背景連結】` establishes that explicit designation.
- Currency/wealth prose remains prose. Importing a description does not initialize
  PR91's cash ledger or authorize payment.
- Weapon descriptions preserve damage, ranges and conditions alongside ammo parsing.
  Retaining prose does not mean all special abilities are automatically executed.
- Manual role imports still derive HP/MP/SAN/MOV/DB/Build through their existing
  constructor. `【原卡衍生數值備註】` preserves source evidence for review, not a state
  override. Supporting printed derived-value overrides is a separate mechanical change.

## Lifecycle changes in this revision

- PDF import no longer queues Chinese translation.
- Bot startup marks old queued/processing jobs paused rather than restarting them.
- `template export/import/preview/approve` is the primary preparation workflow.
- Existing `template generate` remains an explicitly requested optional API operation;
  it is labeled as such in Help. No automatic generation or restart resumes it.
- Original PDFs and existing source extraction/pregen extraction are unchanged.
  Removing automatic *template translation* does not remove the existing PDF/OCR or
  pregen extraction stages.

## Tests

Synthetic source fixtures test export/import compatibility, private file permissions,
unique filenames, blank-template rejection and startup pause without generation.
Role-card tests cover multiline prose, intentional blanks, approximate age, explicit
key connections, retained weapon restrictions and descriptive cash text. The copyrighted
PDFs are local reference material, not test dependencies.
